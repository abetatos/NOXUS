Task ID NOX-013
Feature slug activity-nowcast-signal
Status spec_draft

Technical summary

A new noxus/nowcast/ package turns an activity feature into a weekly, latency-aware surprise nowcast and its QC/incremental-information diagnostics. The pipeline is:

  1. Feature selection (roadmap-contingent, REQ-007/008): pick the highest available feature — VIIRS thermal activity (NOX-011) → NO2 event markers (NOX-004/012) → NO2 intensity residual (NOX-003.1, covariate only). The selected feature is a causal, coverage-screened weekly series.
  2. Expectation baseline (REQ-002): a causal seasonal/trend model of the feature (harmonic-K1 / STL-trend style, fit only on the past) combined additively with the last official CREA print known at each period (publication-lag-aware, REQ-006).
  3. Surprise + causal z (REQ-003/004): surprise = feature − baseline; z = (surprise − expanding-mean) / expanding-std, all from prior periods only.
  4. Latency-aware emission (REQ-005): each z is stamped tradable at the next session after overpass + processing latency.
  5. Triangulation QC (REQ-009/010): compare the nowcast to independent out-of-China quantities; flag divergences with uncertainty.
  6. Incremental-information test vs CREA (REQ-011): the acceptance bar — does the nowcast lead CREA or add orthogonal content beyond CREA's own causal baseline, under NOX-008 robust inference + BH-FDR?

The build is gated by a T1 feasibility spike (REQ-015) that measures feature availability (NOX-011 is blocked) and whether any feature yields incremental information at all, emitting a three-way go/no-go verdict before the rest is implemented. An honest null is a valid terminal outcome.

# noxus/nowcast/features.py
def select_feature(cfg: NowcastConfig) -> FeatureResult:
    """Return the highest-priority AVAILABLE feature series (VIIRS -> events -> NO2 covariate).
    FeatureResult carries: series (weekly, causal), source ('viirs'|'events'|'no2_residual'),
    degraded: bool, reason: str. Never fabricates a VIIRS series when absent (REQ-007/008)."""

# noxus/nowcast/baseline.py  (BENCHMARK model may READ the last published CREA print, but is
# NEVER fit against CREA values, and takes NO market-returns argument — NFR-002)
def expectation_baseline(feature: pd.Series, official_print: pd.Series | None, cfg) -> pd.Series:
    """Causal baseline = own seasonal/trend(feature, past-only) (+) last-known official print,
    publication-lag-aware. Uses expanding/rolling fits; emits NaN during warm-up (EDGE-006)."""

# noxus/nowcast/surprise.py
def build_surprise(feature: pd.Series, baseline: pd.Series, cfg) -> pd.DataFrame:
    """surprise = feature - baseline; z = causal_zscore(surprise); emission_ts = overpass +
    latency -> next session. Columns: feature, baseline, surprise, z, emission_ts, warmup."""

# noxus/nowcast/incremental.py  (REUSES robust_corr / lead_lag / bh_fdr)
def incremental_information(nowcast_z: pd.Series, crea: pd.Series, cfg) -> IncrementalResult:
    """Does the nowcast LEAD CREA (lead_lag) or add ORTHOGONAL content beyond CREA's own causal
    AR/seasonal baseline (partialled residual correlation), under robust_corr + BH-FDR?"""

# noxus/nowcast/triangulation.py  (QC, not a gate)
def triangulation_qc(nowcast: pd.Series, crea: pd.Series, external: dict[str, pd.Series], cfg):
    """Resample to common cadence (never interpolate up). Flag periods where nowcast+external
    consensus diverge from the official print WITH UNCERTAINTY; never labels a series 'fake'."""

# noxus/nowcast/probe.py  (T1 GATE)
def probe(cfg: NowcastConfig) -> ProbeVerdict:
    """Assess feature availability + any-incremental-info-over-CREA. Verdict in
    {GO-primary, GO-degraded, NO-GO} with evidence. Stop-and-record before the build."""

Security and permissions

Credentials (EOG VNF, FIRMS MAP_KEY, any triangulation key) are referenced by environment-variable name only, never read or logged; download URLs are scrubbed of secrets in logs (reuse the NOX-011 convention). No trust-boundary or authz changes. Derived NO2/ VIIRS/price series remain gitignored (reproducibility + provenance discipline). This is not a high-risk category (no auth/payments/migrations/infra), so the deep-review escalation ladder is not triggered on security grounds; see Risks for the methodological deep-review flag.

Test design

  • No-look-ahead guard (AT2/NFR-001): build the nowcast, mutate future feature/print values, rebuild, assert every previously emitted z is unchanged. Also assert emission_ts > observation time.
  • Anti-p-hacking guard (AT3/NFR-002): introspect expectation_baseline/feature-model signatures to assert no market-returns argument and no CREA-values-for-fit argument; assert defaults are constants, not fit against outcomes.
  • Surprise/z correctness (AT1): on a synthetic feature with a known seasonal component, assert baseline removes it causally and z uses only prior periods.
  • Latency + publication-lag (AT2/AT-EDGE-3): assert prints only inform periods on/after publication; conservative lag when unknown.
  • Graceful degradation (AT5/AT-EDGE-1): with VIIRS absent, assert degraded mode + fallback source recorded; no crash.
  • Incremental-information (AT4): planted-lead synthetic where the nowcast leads CREA → robust test detects it; planted-null → BH-FDR rejects nothing.
  • Triangulation QC (AT6): constructed divergence flagged with uncertainty; no "fake" label; monthly-vs-weekly cadence handled without upward interpolation.
  • Honest null (AT7): null feature → report states no edge, no re-tuning.
  • T1 verdict (AT8): synthetic availability scenarios → correct GO-primary / GO-degraded / NO-GO.
  • Reuse regression (AT-REG-1): reused modules unchanged (diff-empty); existing CLI commands still behave.

Risks and trade-offs

  • VIIRS-feature dependency risk (primary risk). The intended primary feature (NOX-011) is blocked on credentials the developer must supply. The nowcast can be built and tested end-to-end on the degraded path, but its scientific verdict on the primary feature is contingent on the VIIRS series existing. This is disclosed as assumption A1 (blocking-for-primary-verdict, non-blocking-for-build) and drives the T1 gate.
  • Low incremental-information risk. NOX-009 (~0 steel-local NO2 change-variance) and NOX-012 (continuous, decoupling coupling) make an honest null a realistic outcome. The design treats null as first-class (REQ-014); the value is a disciplined, no-look-ahead answer to "is there an edge?", not a guaranteed edge.
  • Deep-review flag (methodological, not security). This task makes a quantitative claim of predictive edge over an incumbent. Per the deep-review policy (reference/deep-review-policy.md), the reviewer will apply the escalation ladder to the no-look-ahead and anti-p-hacking guards specifically — surfaced here before implementation so it is not a surprise at review.
  • Scale. Tangshan ≈ 13% of national steel; the nowcast is a cluster signal. Provincial (Hebei) statistics preferred where available (NFR-005). Rejected alternative: presenting it as a national activity nowcast.
  • Triangulation cadence. Shipments/exports are monthly; the QC is therefore a coarse cross-check, not a weekly validator. Rejected alternative: interpolating shipments to weekly (would fabricate data — forbidden).
  • Rejected alternative: using the continuous NO2 residual as the sole feature — falsified by NOX-009; retained only as a covariate.

Rollback plan

The feature is additive: a new noxus/nowcast/ package, new CLI subcommand(s), new config dataclass, new gitignored/committed data dirs. Rollback = remove the package, subcommand registration, and NowcastConfig, and revert the .gitignore / .env.example additions. No existing module is modified beyond additive registration, so reverting cannot regress the existing pipeline. Committed triangulation CSVs can be deleted without affecting other stages.

Design — Placebo AOI control (what does “cluster-local share ≈ 0” mean?)

Task ID NOX-018
Feature slug placebo-aoi-control
Status spec_ready
Author spec-author
Human approvalpending
Origin Paper critique B2 (2026-08-31): the study reports a near-zero share without an empirical null distribution to read it against.

Summary

The paper's load-bearing number is a cluster-local change-variance share of ≈ 0, and its ring sweep shows that number moves with the background geometry. What is missing is a scale for it: what share does this estimator return over a footprint with no blast furnaces at all? Without that, “≈ 0” and “0.061 at 90–150 km” are numbers without a null distribution. This task runs the identical pipeline over a set of matched placebo footprints elsewhere on the North China Plain that contain no BF facilities, producing the empirical distribution of the cluster-local share and of the benchmark correlation under a known-absent signal. It is the calibration that turns the paper's central statistic into an interpretable one. Unlike NOX-017 and NOX-020 it requires new acquisition, so it is gated on a feasibility probe.

Approach

Gate first

T1 is a feasibility probe and nothing else: it measures the openEO transfer volume for one placebo AOI over the full record and extrapolates. The NOX-005 precedent (a throttled portal turning a planned inversion into an N = 4 non-detection) is the reason this task does not begin with acquisition.

Placement

New module noxus/validation/placebo_aoi.py; the variance decomposition and inference stack are imported unchanged, which is the whole point — a placebo run through a different code path would test nothing.

Why eight

Eight placebos give a usable 5th–95th percentile range without turning a calibration into a survey. The number is fixed in advance so that it cannot be extended until the distribution says what we want.

What a null result here means

signal-indistinguishable is the expected outcome and is not a failure: it establishes that ≈ 0 is what this estimator returns when there is nothing to find, which is precisely the calibration the paper currently lacks. It would also sharpen NOX-016's pipeline-suspect verdict, since a pipeline that returns the same answer for Tangshan and for empty plain is one whose null is uninformative about steel.

External dependencies and freshness

Reuses the pinned dependency set in pyproject.toml; no version change is required by this task.

Risks

  • The verdict rule must be committed before the first scoring run, or the result is a chosen verdict rather than a pre-registered one — the defect NOX-015 recorded in its own first pass.
  • Any deviation from the committed estimator would make the comparison to the paper's published numbers invalid; the design imports rather than reimplements.

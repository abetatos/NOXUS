Key verifications (checked against actual code/artifacts)

  1. Two-axis sweep as specified. Axis 1 = clip_cube_to_region using tangshan_aoi(0.25) vs tangshan_aoi(0.10) — a strict isel subset on existing centre coords. Axis 2 = coarsen_cube over {native, 0.10, 0.15, 0.25}° via xr.coarsen(boundary="trim").mean(skipna=True) — block-mean only. CSV confirms all four resolutions × both buffers.
  2. No interpolation-to-finer path exists. grep over gridding.py + scale.py finds interp only in refusal messages and docstrings. coarsen_cube computes fx=round(target/dx) and raises ValueError (ERR-002) when finer than native — no upsampling/reindex/ffill/bfill anywhere.
  3. Robust machinery is real and used. robust_corr composes effective_n (1st-order + NW), block_bootstrap_ci, block_permutation_p; scale_sweep calls it per row and applies bh_fdr within each lag_kind family. AT3 proves the naive p over-rejects AR(1) nulls while the robust tests hold near α; AT4 proves they still recover a planted signal (not merely conservative).
  4. Benchmark-blindness. deseasonalize(...) signature carries no benchmark/CREA argument; _variant_series passes only the NO₂ series + cfg. The sweep computes every scale and reports all with the FDR caveat; the config docstring records that no scale is selected to maximise the benchmark correlation. Honest null is the accepted outcome.
  5. Recorded result faithfully supported. data/derived/scale_sensitivity.csv has exactly 128 rows (64 lag0 + 64 peak; 2 buffers × 4 resolutions × 2 freqs × 4 variants × 2 lag kinds), 0 verdict==robust, 34 fragile (naive-only), all fdr_reject=False, min p_fdr=0.196 — matching scale_sensitivity_findings.txt ("rows: 128 | robust: 0 | fragile: 34") and the tasks.json follow_up ("0/128 … robust after FDR"). Spot-checked Parubets and source-isolation r-values match the CSV to rounding. Tight 0.10 AOI does not rescue; native↔coarse sign flips are near-zero noise.
  6. Documentation targets updated and accurate (see docs re-check below).

Summary

PIVOT (developer-directed, 2026-08-22). This spec was originally built with VIIRS Nightfire (VNF, EOG / Colorado School of Mines) as the primary physical-heat proxy and NASA FIRMS active fire as a cross-check. VNF is now DROPPED. It is no longer public: a VIIRS Nightfire Data Use License (effective 2025-01-10) gates the data, and EOG limits programmatic (OpenID/OAuth) access to paid subscribers (effective 2026-06-01); a free account gives browser-only access, which is not automatable or reproducible. This conflicts with the project's public/free reproducible-data principle, so VNF is out of scope. In its place, the NASA FIRMS active-fire SP-archive is PROMOTED to the PRIMARY physical proxy. Live evidence over the 39-facility bbox (117.9,38.9,119.1,40.3) on 2026-08-22: product VIIRS_SNPP_SP returns type=2 (static-land / industrial) detections over the steel cluster — e.g. 5 detections on 2023-12-15, 73 on 2024-11-20, FRP 0.2–4.8 MW — exactly the intended physical proxy. See the decision log (2026-08-22 — NOX-011 pivot). VNF-specific text below is retained only where it explains why VNF was withdrawn; the acquisition source of record is now FIRMS SP-archive.

Honest caveat baked into this spec. The FIRMS active-fire signal over the plants is sparse and low-FRP — many zero-detection nights — so the statistical power of the triangulation is limited. A weak or null NO₂↔VIIRS or CREA↔VIIRS result is a first-class, valid outcome, not a failure (REQ-025, NFR-005). The feature-vs-target triangulation logic is unchanged: if NO₂ does not track the VIIRS physical heat → the FEATURE is weak; if NO₂↔VIIRS holds but CREA↔VIIRS fails → the TARGET (CREA) is weak.

Acquire an independent, physical activity proxy for the Tangshan steel cluster — VIIRS thermal anomalies over the catalogued steel facilities — and use it to run the decisive triangulation that breaks the feature-vs-target ambiguity raised by critique #1 (the “fraudulent / unverifiable target”). Blast furnaces, sinter plants and coke ovens are high-temperature combustion sources that VIIRS detects from orbit; a space-based thermometer is hard to falsify and cannot be dressed up by any statistical office (“maquillaje”). The CREA benchmark is a commercial trader survey (WIND / Custeel), not official statistics — its provenance is not independently verifiable — so an orthogonal physical proxy is the one remaining lever to localise where the near-null NO₂↔steel result comes from.

The decisive logic (state explicitly). Build a VIIRS thermal series over the facilities and run two correlations under the NOX-008 autocorrelation-robust significance: (i) NO₂ ↔ VIIRS and (ii) CREA ↔ VIIRS. Interpretation:
• If NO₂ does not even track the physical heat of the furnaces → the FEATURE (NO₂ at this scale) is the weak link — consistent with NOX-009's finding that steel-local NO₂ change-variance is ≈0 (SNR-bound).
• If NO₂↔VIIRS holds but CREA↔VIIRS does not → the TARGET (CREA) was the weak link, retroactively re-interpreting every prior near-null.
• If VIIRS↔CREA holds but NO₂ tracks neither → confirms NO₂ is blind at this scale while the target is sound. Every branch is informative: an honest null localises the weak link either way (Morris & Zhang 2019).

This is a new-acquisition task in the style of NOX-002a (TROPOMI): public/free data only, credentials by environment-variable reference only, a resumable manifest, and VIIRS-derived raw outputs gitignored (small stats + figures committable). It is the heaviest task on the roadmap for new data and is independent of NOX-009/010.

Product (source of record after the pivot). The primary thermal series is NASA FIRMS VIIRS active fire, SP (Standard Processing) archive — products VIIRS_SNPP_SP (S-NPP) and VIIRS_NOAA20_SP (NOAA-20), 375 m, free, keyed by a MAP_KEY obtained by email (env var FIRMS_MAP_KEY). The SP archive exposes a detection type column; the type=2 (static-land / industrial) class is the physical proxy for the persistent furnace/sinter/coke hot spots. Per-detection fields: FRP (fire radiative power, MW), brightness temperature, lat/lon, acq date/time, confidence, and type. Access is via the FIRMS per-area CSV/archive API over the AOI bbox. Two properties are load-bearing: (i) the SP archive lags ~2 months behind real time (recent dates are empty — this is expected, not a failure); (ii) the NRT (near-real-time) products lack the type column, so the type=2 industrial filter applies only to the SP archive — which is exactly what the historical 2019+ series is built from. VNF (EOG / CSM) is DROPPED (licence + paid-programmatic-access; not public — see the pivot callout above and assumptions.html A1, open-questions.html Q1). A second-satellite / NRT FIRMS series may be used as an internal consistency check, not as a separate independent product.

Gate. A T1 archive-window probe precedes/validates the full build: fetch a FIRMS SP-archive window over Tangshan inside the ~2-month-lagged archive horizon (not a recent window — a recent window gave a false NO-GO on 2026-08-22 because the SP archive had not yet caught up), confirm type=2 detections land on the facilities, measure per-day volume + available fields + temporal coverage, and record a go/no-go (REQ-000). The probe must be archive-window-aware so it does not misreport an empty recent window as a data absence.

Functional requirements

EARS. IDs group by stage: 000 gate, 001–009 acquisition, 010–019 join + thermal series, 020–029 triangulation, 030–039 verification/output, 040+ CLI.

Viability gate (archive-window probe)

REQ-000Before/while building the acquisition loop, the system shall (T1 probe) fetch a FIRMS SP-archive window over Tangshan inside the ~2-month-lagged archive horizon and record: (a) the archive endpoint + CSV format and the required MAP_KEY credential; (b) per-day / per-window data volume and the implied full-era volume; (c) the detection fields available (FRP MW, brightness temperature, lat/lon, acq date/time, confidence, type); (d) temporal coverage over the AOI (days with ≥1 type=2 detection vs gaps) and the observed archive lag; (e) confirmation that type=2 (static-land) detections spatially co-locate with the catalogued facilities. The probe shall be archive-window-aware: it must query inside the archive horizon and must not report an empty recent window as a data absence (a recent-window probe produced a false NO-GO on 2026-08-22). A go/no-go shall be recorded in open-questions.html (Q1) and the decision log.

Acquisition

REQ-001When acquisition runs, the system shall retrieve FIRMS SP-archive VIIRS active-fire detections over the Tangshan AOI (products VIIRS_SNPP_SP primary + VIIRS_NOAA20_SP) for the configured date range (default: the TROPOMI/CREA overlap era up to the archive horizon), filtering to the AOI bbox and retaining type=2 (static-land / industrial) detections as the physical proxy.
REQ-002When acquiring, the system shall retain, per detection: FRP (fire radiative power, MW), brightness temperature, latitude/longitude, acquisition date/time, confidence, and the type field (SP-archive only). The primary thermal aggregate is derived from FRP (A3).
REQ-003When a day/window is ingested, the system shall persist the AOI-clipped detections reproducibly under data/raw/viirs/, tagged with date range, AOI bbox, product/source (VIIRS_SNPP_SP / VIIRS_NOAA20_SP), and fetch time (provenance).
REQ-004While acquiring the record, the system shall be idempotent and resumable: a manifest records fetched windows; re-running skips completed windows and continues after interruption; acquisition shall support batching by date window with retry/backoff.
REQ-005The FIRMS MAP_KEY credential shall be read from an environment variable via .env (per .env.example, variable name FIRMS_MAP_KEY), referencing the variable name only — never reading, logging, printing, or committing the value (scrub it from any request-URL logging).
REQ-006The system shall support an internal consistency check by comparing the two SP-archive satellites (VIIRS_SNPP_SP vs VIIRS_NOAA20_SP) and, where useful, an NRT product — noting that NRT lacks the type column so the type=2 industrial filter cannot be applied to it. This is an internal consistency check, not a separate independent product (VNF, the former independent cross-check, is withdrawn).
REQ-007[WITHDRAWN 2026-08-22 — VNF dropped.] Retrieve VNF (EOG / CSM) per-night thermal detections as the primary series. VNF is licence-gated (VIIRS Nightfire Data Use License, 2025-01-10) and its programmatic/OAuth access is restricted to paid subscribers (2026-06-01); it is not public/free, so it is out of scope. A missing-VNF code path shall raise a clear licence/pay-gated error rather than attempt a fetch (ERR-006).

Facility join + thermal series

REQ-010When building the thermal series, the system shall join detections to the catalogued steel facilities (data/derived/tangshan_steel_facilities.csv) by assigning each detection to a facility whose centroid lies within a fixed facility radius (config default; A2), discarding detections outside every facility radius.
REQ-011When aggregating, the system shall produce a weekly (primary) and daily (secondary) thermal-activity series over the joined type=2 detections, with the primary aggregate = summed FRP (MW) and alternates = detection count and mean brightness temperature retained alongside (A3). Days/weeks with no detections are zero-filled and flagged (sparse thermal sampling; EDGE-001/005).
REQ-012The thermal series shall be constructed benchmark-blind: the facility radius, quality thresholds, aggregation frequency and primary aggregate are fixed and recorded before the triangulation outputs are viewed (anti-p-hacking; A9, NFR-006). The series must not reference the CREA benchmark or the NO₂ result in its construction.

Triangulation

REQ-020When triangulation runs, the system shall compute NO₂-footprint ↔ VIIRS correlation (Pearson r + lead/lag) under the NOX-008 autocorrelation-robust significance by reusing noxus/validation/robust.py (robust_corr) — effective-N, Newey-West, moving-block bootstrap CI, block-permutation null. It shall not re-implement significance.
REQ-021When triangulation runs, the system shall compute CREA ↔ VIIRS correlation (Pearson r + lead/lag) under the same robust significance, on the common overlap window.
REQ-022The system shall apply Benjamini-Hochberg FDR (bh_fdr) across the family of correlation p-values (NO₂↔VIIRS, CREA↔VIIRS, and the two-satellite consistency pair) so the multiplicity is corrected transparently.
REQ-023The system shall emit an interpretation / decision table that maps the observed pattern of significant links onto the feature-vs-target diagnosis (NO₂ blind → feature is the weak link; CREA↔VIIRS absent while NO₂↔VIIRS holds → target was the weak link; VIIRS↔CREA holds while NO₂ tracks neither → NO₂ blind, target sound), including the honest-null branch. The triangulation logic is unchanged by the pivot; only the VIIRS product feeding it changed.
REQ-024The system shall repeat the triangulation on the second SP-archive satellite (VIIRS_NOAA20_SP vs VIIRS_SNPP_SP) as an internal consistency check, reporting whether the diagnosis is consistent across the two satellites (REQ-006). There is no longer a separate independent cross-check product (VNF withdrawn).
REQ-025The system shall report statistical power honestly: the effective sample size, the fraction of zero-detection weeks, and the FRP magnitude range shall be surfaced alongside every correlation, and the interpretation shall state that the FIRMS active-fire signal over the plants is sparse and low-FRP so a weak or null result is a first-class, valid outcome (not a failure) with limited power to distinguish the feature-vs-target branches. No result shall be massaged toward significance.
REQ-026The system shall handle the ~2-month SP-archive lag explicitly: the acquisition and probe shall treat the archive horizon as a known bound, empty recent windows shall be reported as expected archive lag (not a data absence or failure), and the analysis window shall end at the most recent date the SP archive actually covers (never padded/interpolated to real time).

Verification + output

REQ-030Verification shall render the VIIRS detections over the AOI with the steel-facility locations overlaid, so a reviewer can confirm the thermal detections co-locate with the steel facilities (reusing the facilities CSV + overlay convention).
REQ-031The system shall emit small, committable outputs under data/derived/: the thermal-activity series and the triangulation result table (CSV/parquet + figures). VIIRS-derived raw detections stay gitignored (NFR-003).

CLI

REQ-040When the user runs acquisition, series-build, triangulation and verification via the noxus CLI, the system shall expose them as documented subcommands (e.g. fetch-viirs with a --probe archive-window-probe mode and a --source selector (firms-snpp-sp/firms-noaa20-sp), build-thermal-series, triangulate-thermal, verify-viirs) driven by noxus/config/ (AOI/buffer, date range, source, facility radius, quality thresholds, frequency, budget).

Non-functional requirements

NFR-001Reproducibility. Acquisition, join and triangulation are parameterised and provenance-tagged; given the same config and source state, the kept dataset and the triangulation table are reproducible (fixed RNG seeds via robust_corr).
NFR-002Public/free + credentials by reference. Uses only free NASA FIRMS (SP archive). The FIRMS_MAP_KEY is read from .env per .env.example; the variable name is referenced, the value never read into logs/output or committed. VNF is excluded because it is no longer free/public (licence + paid programmatic access) — the public/free principle is the reason it was dropped.
NFR-003Storage discipline. VIIRS-derived raw detections live under gitignored data/raw/viirs/; only small derived stats + figures are committable (data/derived/).
NFR-004Stack conformance. Python ≥3.12; passes uv run ruff check . and uv run pytest; downloads via the existing httpx stack; the facility-radius join uses a numpy haversine (no new geospatial dependency). No new dependency shall be added without developer approval (Q5).
NFR-005Honest null is designed-for and informative. A null (no significant correlation) is a valid, reportable outcome; the value of this task is that every branch localises the weak link (see the decisive logic). No result is massaged to reach significance.
NFR-006Anti-p-hacking / pre-registration. The facility radius, quality thresholds, aggregation frequency and primary aggregate are fixed and recorded (in assumptions.html) before the triangulation is viewed; the thermal series is built benchmark-blind (REQ-012).
NFR-007Politeness. Downloads are rate-limited / sequential with retry+backoff to respect the free services; the run is resumable so it can span sessions.
NFR-008Additive. No change to existing TROPOMI/ERA5/benchmark/attribution behaviour; VIIRS is a parallel acquisition + analysis channel. Existing modules and outputs are untouched.

Edge cases

EDGE-001A night with no detections over the AOI (cloud, no overpass, or genuinely no hot spot) → recorded as zero-activity for that night, not an error and not interpolated (honest gaps, same policy as TROPOMI coverage).
EDGE-002A detection falls within the radius of more than one facility (facilities are dense) → assigned to the nearest facility centroid; a detection outside every radius is dropped from the facility series (REQ-010).
EDGE-003The VIIRS overlap era is shorter than the CREA / NO₂ series → triangulation aligns on the common window; effective-N shrinks accordingly and is reported (never padded).
EDGE-004FIRMS SP-archive returns detections tagged as presumed vegetation fire (type=0) / offshore (type=3) / volcano (type=1) rather than static land source (type=2) → filtered out, keeping only type=2 for the industrial series (REQ-001).
EDGE-005A weekly bin has very few or zero detection-days (sparse, low-FRP thermal sampling — the expected regime here) → the aggregate is zero-filled and the sparse-coverage weeks are flagged so downstream can weight/exclude them and so power is reported honestly (REQ-025).
EDGE-006The two SP-archive satellites (VIIRS_SNPP_SP vs VIIRS_NOAA20_SP) disagree in coverage (different overpass times / mission spans) → each is aggregated independently; the triangulation reports both, and REQ-024 flags any diagnosis divergence rather than blending them.
EDGE-007A queried window falls after the ~2-month SP-archive horizon → the API returns empty; the system records this as expected archive lag, not a data absence, and does not emit a NO-GO on that basis (REQ-026; this is the false-NO-GO trap that motivated the pivot probe fix).

Error states

ERR-001If a required credential (e.g. FIRMS_MAP_KEY) is missing/invalid, the system shall fail with a clear message referencing the environment-variable name — never echoing the value.
ERR-002If the download endpoint returns an error / empty listing for a date range, or the expected detection fields are absent from a product, the system shall raise a descriptive error naming the source/date/field attempted.
ERR-003If a download fails irrecoverably for a batch, the system shall record the failure, leave already-fetched nights intact, and allow a resume (REQ-004).
ERR-004If the measured per-window / full-era download volume (REQ-000) exceeds the configured budget threshold, the system shall stop and surface the no-go rather than silently starting an oversized download.
ERR-005If the facilities CSV is missing or malformed, the join step shall raise a descriptive error rather than silently producing an empty series.
ERR-006If a VNF acquisition path is invoked (e.g. legacy config or an explicit --source vnf), the system shall raise a clear licence/pay-gated error stating that VNF is withdrawn (VIIRS Nightfire Data Use License 2025-01-10; paid programmatic access 2026-06-01) and directing the user to the FIRMS SP-archive source — never attempting an (impossible/non-reproducible) VNF fetch.
ERR-007If the NRT filter is asked to apply a type=2 selection, the system shall raise a descriptive error noting that NRT products lack the type column and that the industrial filter is only valid on the SP archive.

Acceptance criteria

AC-000The T1 archive-window probe produces a recorded measurement of the FIRMS SP-archive endpoint/format, MAP_KEY requirement, per-window volume, available fields (incl. type), AOI temporal coverage + observed archive lag, and type=2 facility co-location — plus a written go/no-go. The probe queries inside the archive horizon (no false NO-GO from a recent window).
AC-001A small date-range acquisition over the AOI (inside the archive horizon) returns AOI-clipped type=2 FIRMS SP detections with the required fields + provenance, and re-running skips completed windows (idempotent/resumable), keeping raw detections gitignored.
AC-002The join + aggregation produces a weekly (primary) and daily (secondary) thermal-activity series over the facilities (summed FRP primary; count + mean brightness-temperature alternates), constructed benchmark-blind, zero-filled with sparse-coverage weeks flagged.
AC-003The triangulation emits NO₂↔VIIRS and CREA↔VIIRS robust_corr results (r, effective-N, bootstrap CI, permutation p) with BH-FDR across the family and an interpretation table covering the honest-null branch — reusing robust.py, not re-implementing significance — and surfaces the power caveat (n_eff, zero-week fraction, FRP range; REQ-025).
AC-004The two-satellite (SNPP vs NOAA20) internal consistency check runs the same triangulation and the report states whether the diagnosis is consistent across the two satellites. A VNF request raises the licence/pay-gated error (AC-007).
AC-005Verification renders VIIRS detections over the AOI with facility points overlaid (co-location check); committable series + triangulation table + figures land under data/derived/.
AC-006uv run pytest and uv run ruff check . pass; all network/auth is mocked in tests (synthetic detection fixtures, no network).
AC-007Invoking a VNF acquisition path raises a clear licence/pay-gated error (ERR-006) and never attempts a fetch; the NRT type=2 filter raises the descriptive guard error (ERR-007).

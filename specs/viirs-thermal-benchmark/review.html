Focused scrutiny (the point of the task)

  1. Anti-p-hacking / benchmark-blindness — PASS. join_to_facilities(detections, facilities, radius_km) and build_thermal_series(joined, freq, aggregate, ...) take no CREA/NO₂ argument. signal/thermal.py imports only column constants from viirs.py plus numpy/pandas — it never imports noxus.data.benchmark or any NO₂ series. Radius (3 km), freq (W) and primary aggregate (radiant heat) are fixed in ThermalTriangulationConfig and recorded in assumptions.html (A2/A3/A9) before any result. test_series_build_is_benchmark_blind asserts both signatures and the absence of benchmark coupling in source.
  2. Significance reuse — PASS. viirs_triangulation.py imports robust_corr, bh_fdr, RobustCorr, lead_lag from noxus.validation and calls them unchanged; no significance math is re-implemented. git diff confirms robust.py and leadlag.py are byte-for-byte unchanged. test_triangulate_matches_direct_robust_corr asserts the link equals a direct robust_corr call (r and p_perm).
  3. Feature-vs-target diagnosis — PASS. All four branches wired in interpret: (no,yes)→NO₂ blind/target sound; (yes,no)→target weak; (yes,yes)→coherent; (no,no)→honest null. Three branches exercised end-to-end via triangulate on synthetic series; the coherent branch is covered at the unit level (see nit N4). BH-FDR is applied across the family and significance is additionally gated on n_common >= min_overlap.
  4. Credential / security — PASS. FIRMS_MAP_KEY read by name via dotenv; missing-key error names the variable and never echoes a value; _scrub_url strips the key path segment before any error surfaces; VNF error messages carry only the (secretless) VNF URL. .env untouched; data/raw/viirs/ gitignored; only small derived stats/figures are committable. Tests cover the missing-key and scrub paths. (See non-blocking nit N3 on scrub robustness.)
  5. T1 honesty — PASS. The probe finding is real and honestly recorded: Q1 documents that the defaulted VNF path returns an HTTP-200 Keycloak HTML login (VNF is not keyless), the fetcher raises a clear ViirsAuthError on an HTML/login body, the go/no-go is marked blocked-on-live-run, and the Q1 decision is left Pending — not silently answered. No fabricated T1 result is claimed anywhere in the code or spec.
  6. Acceptance-test coverage — PASS. Every AT0–AT7 + AT-EDGE-1/2 + AT-ERR-1 + AT-REG-1 maps to at least one implemented test (table above). No acceptance criterion is left without a test.

Findings (non-blocking nits)

  • N1 — probe auth_required heuristic mislabels VNF. noxus/data/viirs.py:488 sets auth_required = cfg.source == "firms", so a VNF probe prints auth_required=False despite the T1 finding that VNF sits behind EOG SSO. The honest finding lives in Q1 and the fetcher raises ViirsAuthError, but the probe's own field is misleading. Cheap fix: derive it from the fetched response (HTML/login ⇒ True) or drop the hardcoded default. Developer-run field only — non-blocking.
  • N2 — CLI empty-store test exits via the wrong branch. tests/cli/test_cli.py::test_build_thermal_series_empty_store_returns_1 chdirs to an empty tmp dir, so the command returns 1 from the missing-facilities-CSV (FacilitiesError) branch, not the empty-store branch it is named for. Both branches return 1 and are individually reachable; the test name overstates what it exercises. Non-blocking test-clarity nit.
  • N3 — _scrub_url is coupled to the literal /csv/ segment. Scrubbing works for the current FIRMS endpoint (.../api/area/csv/<key>/...), but if firms_endpoint_base were reconfigured without /csv/ the key could leak into an error. Scrubbing by the actual key value would be more robust. Non-blocking (current config is safe).
  • N4 — coherent-branch not exercised end-to-end. DIAG_COHERENT is covered only via the interpret(True, True) unit test, not through a full triangulate run (the other three branches are). Low value to add; noted for completeness. Non-blocking.

All four are non-blocking. Per the completion policy they must be resolved or explicitly deferred with justification before the task is marked done; since the task is data-gated and not yet done, they are recorded here for the implementer to sweep during the T12/T14 pass. Recommended deferral: N2/N4 (test clarity) and N3 (defensive hardening) may be deferred; N1 should be fixed in the T12 pass so the developer's live probe output is not misleading.

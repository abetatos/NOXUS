Purpose

Acceptance-level scenarios that must hold for the feature to be accepted. They describe observable behavior, not final test code. The implementer creates automated tests from them (synthetic fixtures, no network); the reviewer verifies coverage.

Test strategy

The acceptance tests must verify: acquisition + AOI clip + provenance + resumability; the facility-radius join and aggregation; benchmark-blind construction; the triangulation via the reused robust.py; the interpretation table incl. the honest-null branch; the FIRMS cross-check; verification rendering; error handling; and that existing behavior is unchanged.

Testing style configured for this project

pytest; network/credentials mocked via an injected fetcher seam (as in tests for tropomi.py);
significance exercised through the real noxus/validation/robust.py on tiny arrays (not mocked).

Test command

uv run pytest
uv run ruff check .

Manual acceptance checklist

  • All requirements have at least one acceptance test.
  • Main success path (acquire → join → triangulate) is covered.
  • Empty/sparse states are covered.
  • Invalid input / error paths are covered (no secret echoed).
  • Significance is reused from robust.py, not re-implemented.
  • Thermal series is benchmark-blind; radius/aggregate pre-registered.
  • Honest-null branch is a first-class, tested outcome.
  • Non-goals (existing paths) are protected.
  • Tests are feasible offline with synthetic fixtures.
  • Any unresolved behavior is listed in open-questions.html.

Design — VIIRS thermal-anomaly independent benchmark

Task ID NOX-011
Feature slug viirs-thermal-benchmark
Status spec_draft

Technical summary

Three additive pieces in the shape of NOX-002a (acquisition) + NOX-008 (analysis):

  1. Acquisition — a new noxus/data/viirs.py: a resumable loop that, per date-batch, retrieves VNF per-night thermal detections, filters them to the Tangshan AOI bbox client-side, and writes per-night AOI-clipped detections under gitignored data/raw/viirs/ with a JSON manifest and provenance. The network interaction sits behind a Fetcher seam (Protocol, exactly like tropomi.py) so the clip/persist/manifest logic is unit-testable without network or keys. FIRMS is an alternate fetcher implementing the same seam.
  2. Facility join + thermal series — a new noxus/signal/thermal.py: joins detections to the catalogued facilities within a fixed radius (numpy haversine, no geopandas), then aggregates to a weekly (primary) and daily (secondary) thermal-activity series — summed radiant heat (MW) primary, detection count and mean temperature as alternates. Built benchmark-blind: the function takes only detections + facilities + fixed parameters, never CREA/NO₂.
  3. Triangulation — a thin orchestration module analysis/viirs_triangulation.py (in the shape of analysis/variance_decomposition.py) that aligns the thermal series with the existing NO₂-footprint and CREA series on the common window and calls noxus.validation.robust.robust_corr / bh_fdr (and leadlag) to produce the NO₂↔VIIRS and CREA↔VIIRS correlations, the BH-FDR family, and the interpretation table. Significance is reused, never re-implemented.

Gate. Task T1 is a feasibility spike: fetch a small VNF window over Tangshan, confirm detections land on the facilities, measure per-night volume + fields + temporal coverage, and record a go/no-go against a configured download budget before the loop is built. The exact VNF endpoint/format/auth and per-night volume are the external-access unknowns (Q1); they are safe-defaulted so the spec is complete, and pinned empirically at T1.

Security and permissions

The only credential is an optional FIRMS MAP_KEY read from .env via python-dotenv; it is referenced by variable name only and never logged, printed, or committed (if it appears in a request URL, request-URL logging must be scrubbed — same discipline as tropomi.py). VNF is expected keyless. Network egress is limited to the EOG / FIRMS hosts. No protected files are written; no remote mutations. This is a security-sensitive integration only in the mild sense of API-key handling; it is not a high-risk deep-review category (no auth/authz surface, payments, migrations, or infra). Standard review applies.

Test design

  • Mocked fetcher: a fake ViirsFetcher returns synthetic per-night detection frames (some on facilities, some off, some empty nights) so acquire→clip→retain fields→persist→manifest is tested without network/key (AT1); resumability: run twice, second run fetches nothing new; mid-range interruption resumes (AT2).
  • Radius join: synthetic detections at known offsets from facility centroids → assigned to the nearest within radius, ties resolved, outside-radius dropped (AT3a, EDGE-002).
  • Aggregation: synthetic joined detections → weekly/daily summed radiant heat, detection count, mean temperature correct; empty/sparse weeks flagged (AT3b, EDGE-001/005).
  • Benchmark-blind: assert the series-build signature takes no CREA/NO₂ argument (AT3c, REQ-012).
  • Triangulation: feed a synthetic thermal series correlated with a synthetic NO₂ and uncorrelated with a synthetic CREA (and vice-versa) → assert robust_corr is called and the interpretation table selects the correct feature-vs-target branch, incl. the honest-null branch (AT5/AT6); BH-FDR applied across the family (REQ-022). Significance functions are exercised via the real robust.py, not mocked, on tiny arrays.
  • FIRMS cross-check: synthetic FIRMS frame with mixed detection types → only static-land-source retained; cross-check triangulation runs (AT4, EDGE-004).
  • Verification: synthetic store → render writes a PNG with facility markers (AT7; real-data visual check manual).
  • Errors: missing/invalid key (no value echoed), endpoint/field-not-found, download failure/resume, budget no-go, bad facilities CSV (AT-ERR-1).
  • Regression: existing CLI subcommands + TROPOMI/CREA paths unchanged (AT-REG-1).

Risks and trade-offs

  • External-access unknowns (the gate). The exact VNF endpoint/format, whether auth is needed, and the per-night volume are not verifiable without web access. Mitigation: safe defaults (VNF primary, per-night CSV, keyless) + the T1 spike that measures and records a go/no-go (REQ-000, ERR-004) before the loop is built — the GEMS/NOX-007 precedent. This is the main reason for the spike-gated structure.
  • Honest null is designed-for and informative. A null NO₂↔VIIRS is a valid outcome and, combined with CREA↔VIIRS, localises the weak link either way (the whole point). No result is massaged toward significance (NFR-005). This is called out here so nobody treats a null as a failure at review time.
  • Detection sparsity / VNF vs FIRMS coverage. Night-only sampling, cloud, and sub-detection-threshold furnaces can make the thermal series sparse; sparse weeks are flagged (EDGE-005) and effective-N shrinks honestly (EDGE-003). VNF and FIRMS may disagree; they are kept independent and any diagnosis divergence is reported, not blended (REQ-024, EDGE-006).
  • Multiple testing. Several correlations are computed → BH-FDR across the family (REQ-022) and pre-registered radius/thresholds/aggregate (NFR-006) guard against a false positive.
  • Facility-set count discrepancy (Q6). The committed facilities CSV holds ~39 rows, while roadmap text references “84”; the committed CSV is treated as the source of truth (A7). Impact if wrong: the join target differs — non-blocking, flagged for developer confirmation.
  • Interpretation is diagnostic, not causal. VIIRS radiant heat is a proxy for furnace thermal state, not a direct production measurement; the triangulation localises the weak link but does not by itself prove causation. Stated in the interpretation table.
  • Rejected alternatives: (a) FIRMS as the primary series — it is active-fire-tuned, so VNF (industrial-combustion-tuned, reports radiant heat/temperature) is the better primary and FIRMS the cross-check; (b) adding geopandas/shapely for the join — unnecessary for a point-in-radius test, a numpy haversine avoids a heavy dependency; (c) re-implementing significance — forbidden; reuse robust.py; (d) day+night VIIRS products — night-only VNF is sufficient for 24/7 steel baseload and is the cleaner thermal product.

Rollback plan

Additive: new modules behind new CLI subcommands; TROPOMI/ERA5/CREA/attribution paths untouched. Rollback = revert the branch and delete data/raw/viirs/ (gitignored) + the VIIRS derived artifacts. If the T1 go/no-go is a no-go, the task stops with the measurement recorded and no loop is built — nothing downstream depends on it.

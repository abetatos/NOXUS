Design — VIIRS thermal-anomaly independent benchmark

Task ID NOX-011
Feature slug viirs-thermal-benchmark
Status in_progress (FIRMS-primary pivot, 2026-08-22)

Technical summary

PIVOT (developer-directed, 2026-08-22). VNF (EOG / CSM) is dropped — no longer public (VIIRS Nightfire Data Use License 2025-01-10; paid programmatic access 2026-06-01), which breaks the project's free/reproducible-data principle. The NASA FIRMS SP-archive is now the PRIMARY physical proxy: products VIIRS_SNPP_SP + VIIRS_NOAA20_SP, filtered to type=2 (static-land / industrial) detections over the AOI, keyed by FIRMS_MAP_KEY. Two design-shaping facts: the SP archive lags ~2 months (recent windows are empty by design), and the NRT products lack the type column (so type=2 filtering, and hence the historical 2019+ series, is SP-only). Full rationale + live evidence: decision log 2026-08-22.

Three additive pieces in the shape of NOX-002a (acquisition) + NOX-008 (analysis):

  1. Acquisition — a new noxus/data/viirs.py: a resumable loop that, per date-window, retrieves FIRMS SP-archive VIIRS active-fire detections over the Tangshan AOI bbox, keeps type=2 (static-land) detections, and writes AOI-clipped detections under gitignored data/raw/viirs/ with a JSON manifest and provenance. The network interaction sits behind a Fetcher seam (Protocol, exactly like tropomi.py) so the clip/persist/manifest logic is unit-testable without network or keys. The two SP-archive satellites (SNPP, NOAA20) are alternate fetchers on the same seam; a VNF path raises a licence/pay-gated error.
  2. Facility join + thermal series — a new noxus/signal/thermal.py: joins detections to the catalogued facilities within a fixed radius (numpy haversine, no geopandas), then aggregates to a weekly (primary) and daily (secondary) thermal-activity series — summed radiant heat (MW) primary, detection count and mean temperature as alternates. Built benchmark-blind: the function takes only detections + facilities + fixed parameters, never CREA/NO₂.
  3. Triangulation — a thin orchestration module analysis/viirs_triangulation.py (in the shape of analysis/variance_decomposition.py) that aligns the thermal series with the existing NO₂-footprint and CREA series on the common window and calls noxus.validation.robust.robust_corr / bh_fdr (and leadlag) to produce the NO₂↔VIIRS and CREA↔VIIRS correlations, the BH-FDR family, and the interpretation table. Significance is reused, never re-implemented.

Gate. Task T1 is an archive-window probe: fetch a FIRMS SP-archive window over Tangshan inside the ~2-month archive horizon (a recent window gives a false NO-GO because the SP archive has not caught up — this is the exact bug that motivated the pivot's probe fix), confirm type=2 detections land on the facilities, measure per-window volume + fields + temporal coverage + observed lag, and record a go/no-go. The probe must report an empty recent window as expected archive lag, not a data absence (REQ-000, REQ-026, EDGE-007).

Security and permissions

The only credential is the FIRMS MAP_KEY (now required, since FIRMS is the primary source) read from .env via python-dotenv; it is referenced by variable name only and never logged, printed, or committed (it appears in the FIRMS request URL, so request-URL logging must be scrubbed — same discipline as tropomi.py). Network egress is limited to the FIRMS host. No protected files are written; no remote mutations. This is a security-sensitive integration only in the mild sense of API-key handling; it is not a high-risk deep-review category (no auth/authz surface, payments, migrations, or infra). Standard review applies.

Test design

  • Mocked fetcher: a fake ViirsFetcher returns synthetic per-window detection frames with mixed type (some on facilities, some off, some empty windows) so acquire→clip→type=2 filter→persist→manifest is tested without network/key (AT1); resumability: run twice, second run fetches nothing new; mid-range interruption resumes (AT2).
  • Radius join: synthetic detections at known offsets from facility centroids → assigned to the nearest within radius, ties resolved, outside-radius dropped (AT3a, EDGE-002).
  • Aggregation: synthetic joined detections → weekly/daily summed FRP, detection count, mean brightness temperature correct; empty bins zero-filled and sparse weeks flagged (AT3b, EDGE-001/005).
  • Benchmark-blind: assert the series-build signature takes no CREA/NO₂ argument (AT3c, REQ-012).
  • Triangulation: feed a synthetic thermal series correlated with a synthetic NO₂ and uncorrelated with a synthetic CREA (and vice-versa) → assert robust_corr is called and the interpretation table selects the correct feature-vs-target branch, incl. the honest-null branch (AT5/AT6); BH-FDR applied across the family (REQ-022). Significance functions are exercised via the real robust.py, not mocked, on tiny arrays.
  • Type=2 filter + two-satellite consistency: synthetic SP frame with mixed type values → only type=2 (static-land) retained; the SNPP-vs-NOAA20 consistency check runs (AT4, EDGE-004/006). A synthetic NRT frame (no type column) → the type=2 filter raises the descriptive guard error (ERR-007). Invoking the VNF path → ViirsLicenceError (ERR-006).
  • Archive-lag / probe: a fetcher returning empty for a post-horizon window → recorded as expected lag, not a NO-GO (AT9, REQ-026/EDGE-007); the probe reports the observed lag.
  • Verification: synthetic store → render writes a PNG with facility markers (AT7; real-data visual check manual).
  • Errors: missing/invalid key (no value echoed), endpoint/field-not-found, download failure/resume, budget no-go, bad facilities CSV (AT-ERR-1).
  • Regression: existing CLI subcommands + TROPOMI/CREA paths unchanged (AT-REG-1).

Risks and trade-offs

  • Source availability was the gate (now resolved by the pivot). VNF turned out to be licence/pay-gated (not public), and the FIRMS --probe initially returned a false NO-GO because it tested a recent window against the ~2-month-lagged SP archive. Resolution: drop VNF, promote FIRMS SP-archive, and make the probe archive-window-aware (REQ-000, REQ-026, EDGE-007). This is the load-bearing risk that the pivot addresses.
  • Sparse, low-FRP signal → limited statistical power (the key honest caveat). The FIRMS active-fire signal over the plants is sparse (many zero-detection nights) and low-FRP (0.2–4.8 MW observed). The triangulation therefore has limited power to distinguish the feature-vs-target branches, and a weak or null result is a first-class, valid outcome, not a failure (REQ-025, NFR-005). Power (n_eff, zero-week fraction, FRP range) is reported alongside every correlation. Called out here so nobody treats a null as a failure at review time. The triangulation logic is unchanged by the pivot.
  • Detection sparsity / two-satellite coverage. Overpass timing, cloud, and sub-detection-threshold furnaces make the series sparse; empty bins are zero-filled and sparse weeks flagged (EDGE-005), effective-N shrinks honestly (EDGE-003). The two SP satellites (SNPP, NOAA20) may disagree; they are kept independent as an internal consistency check and any diagnosis divergence is reported, not blended (REQ-024, EDGE-006).
  • Archive lag (~2 months). The SP archive trails real time; the analysis window ends at the archive horizon and empty recent windows are recorded as expected lag, never as a data absence or NO-GO (REQ-026, EDGE-007). NRT could extend recency but lacks the type column, so it cannot carry the industrial filter and is used only as an internal consistency check (ERR-007).
  • Multiple testing. Several correlations are computed → BH-FDR across the family (REQ-022) and pre-registered radius/thresholds/aggregate (NFR-006) guard against a false positive.
  • Facility-set count discrepancy (Q6). The committed facilities CSV holds ~39 rows, while roadmap text references “84”; the committed CSV is treated as the source of truth (A7). Impact if wrong: the join target differs — non-blocking, flagged for developer confirmation.
  • Interpretation is diagnostic, not causal. VIIRS FRP is a proxy for furnace thermal state, not a direct production measurement; the triangulation localises the weak link but does not by itself prove causation. Stated in the interpretation table.
  • Rejected alternatives: (a) keeping VNF by paying for an EOG subscription — rejected: breaks the project's free/public reproducibility principle; (b) manual browser VNF downloads — rejected: not automatable/reproducible; (c) accepting the probe's false NO-GO and abandoning FIRMS — rejected: the SP archive demonstrably shows the type=2 signal is there (live evidence 2026-08-22); (d) using NRT for the industrial series — rejected: NRT lacks the type column, so type=2 cannot be applied; (e) adding geopandas/shapely for the join — unnecessary for a point-in-radius test, a numpy haversine avoids a heavy dependency; (f) re-implementing significance — forbidden; reuse robust.py.

Rollback plan

Additive: new modules behind new CLI subcommands; TROPOMI/ERA5/CREA/attribution paths untouched. Rollback = revert the branch and delete data/raw/viirs/ (gitignored) + the VIIRS derived artifacts. If the T1 go/no-go is a no-go, the task stops with the measurement recorded and no loop is built — nothing downstream depends on it.

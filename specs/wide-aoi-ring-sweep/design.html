Design — Wide-AOI ring sweep (NOX-017)

Task IDNOX-017
PrincipleWiden the domain; change nothing else. One knob moves.

Approach

The existing sweep machinery (noxus/signal/ring_sweep.py) is already fully config-driven: cube paths, ring grid, weightings, thresholds. The wide run is therefore the same code over a wider cube, plus three small enabling changes:

  1. a --raw-dir argument on noxus fetch, so the wide acquisition cannot collide with the committed narrow store;
  2. a coverage_bbox option in gridding, so the temporal mask stays identical;
  3. an aoi passed through the sweep into background_ring, so wide rings are not clipped back to the narrow box.

Each of the three defaults to today's behaviour. Nothing on the committed paths changes.

Change 1 — noxus fetch --raw-dir

acquire_no2 already reads cfg.raw_dir and is resumable through manifest.json inside that directory. The CLI simply never exposed it. Without the flag a wide fetch would land in data/raw/tropomi/, where every date is already in the manifest — so it would fetch nothing, and any date it did fetch would silently mix two geometries into one store.

p_fetch.add_argument("--raw-dir", help="raw store (default: data/raw/tropomi)")
...
cfg = replace(cfg, ..., raw_dir=Path(args.raw_dir) if args.raw_dir else cfg.raw_dir)

Wide store: data/raw/tropomi_wide/ (gitignored under data/raw/).

Change 2 — coverage sub-box in gridding (REQ-004)

Today composite() computes

period_coverage = (valid >= cfg.min_cell_obs).mean(dim=["y", "x"])
no2_mean = no2_mean.where(period_coverage >= cfg.min_period_coverage)

over every cell of the box. A 4.84×-larger box changes which periods survive, so n would move at the same time as the ring and the comparison with NOX-015 would be confounded. GriddingConfig.coverage_bbox: tuple[float, float, float, float] | None = None restricts the coverage reduction to a sub-box while leaving the data itself untouched:

valid_cov = valid if cfg.coverage_bbox is None else _clip_bbox(valid, cfg.coverage_bbox)
period_coverage = (valid_cov >= cfg.min_cell_obs).mean(dim=["y", "x"])

None is the default and reproduces current behaviour exactly. The wide run passes the committed 0.25°-buffer AOI bbox, so the surviving period set is decided by the same geography as the committed cube.

Change 3 — AOI plumbing into the ring (REQ-010)

background_ring(..., aoi=None) falls back to the module-level TANGSHAN (buffer 0.25°) and clips the ring to it. On a wide cube that would silently discard every cell beyond the narrow box — the wide rings would be identical to the narrow ones and the run would look like a plateau that is really a clip. The aoi is threaded:

RingSweepConfig.aoi_buffer_deg: float | None = None   # None => TANGSHAN, today's behaviour
  → _levels_for_ring(...)  → _level_series_for_cube(..., aoi=aoi)
                            → background_ring(..., aoi=aoi)

ring_geometry is computed from the realised mask, so the audit reflects whatever the clip actually produced.

Verdict logic (REQ-020..023)

rule_a = LEVEL: share_local(outermost) > 0.05 and CI excludes 0,  in >= 2 cells
rule_b = RISE : share_local(outermost) - share_local(25-60) > 0.05,
                with the outermost CI excluding 0,               in >= 2 cells
plateau = |share_local(outermost) - share_local(second-outermost)| < 0.01, in >= 2 cells

verdict = "self-subtraction"        if rule_a and rule_b
        | "ring-robust"             if (not rule_a) and (not rule_b) and plateau
        | "domain-limited"          if (not plateau)          # rise still climbing at the edge
        | "rules-disagree"          otherwise                 # reported, never silently resolved

“Outermost” is keyed on the (inner, outer) pair, not on the inner radius — the NOX-015 pooling bug where inner == 60 matched two distinct rings. The existing regression test covers it and is extended to the new grid.

Execution plan

  1. Wide acquisition, background, resumable: ~89 month-batches, ~2.0 h, ~200 MB.
  2. Grid weekly + daily with coverage_bbox = committed AOI.
  3. Compare the retained period set against the committed cubes (REQ-005).
  4. Run the wide sweep; emit CSV + findings note.
  5. Update paper §6.3; state plainly what it does and does not settle.

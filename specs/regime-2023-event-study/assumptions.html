A5 Regime segmentation uses a fixed pre-registered rule, not a CREA-tuned boundary Pending
Assumption
Regimes are segmented by a fixed rule declared before viewing outcomes — the rolling-18-month peak-centred window for the "2023 regime" and a fixed calendar-year split for the "2024 collapse" — with a boundary-robustness sweep reported. The boundary is never chosen to maximise the within-regime correlation.
Reason
Choosing the boundary against CREA would manufacture the peak (anti-p-hacking, NFR-005). A fixed rule + a robustness sweep keeps the segmentation honest.
Risk level
Medium
Impact if wrong
If the fixed boundary is slightly off the true regime edge, the within-regime r is attenuated (conservative), never inflated. Paired with Q4.

A6 Scan-maximum null via block-permutation reusing the NOX-008 tooling Pending
Assumption
The rolling-window scan-maximum null (REQ-030) is built by a serial-dependence-preserving null — moving-block permutation / phase-randomisation of one series — reusing noxus.validation.robust's block tooling, then taking the MAX rolling-18-month r across the overlapping windows per draw. The observed peak's percentile against that distribution is the reported significance.
Reason
Consistency with the project's established significance tooling (NOX-008); it correctly answers "is 0.76 surprising given how many overlapping windows were scanned" without a new statistical convention.
Risk level
Medium
Impact if wrong
Block length too short understates the null spread (over-rejects the null → peak looks too significant); too long wastes power. Mitigated by reusing the NOX-008 block-length rule and reporting the block length used.

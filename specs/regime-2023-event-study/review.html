Non-blocking findings — MUST be resolved before done (and before the T12 real run)

  • F1 (significant) — the event-study precision/recall/lead table is orphaned from all outputs. regime_event_study() is implemented and unit-tested (AT5) but is never called by the regime_study() driver; RegimeArtifacts carries no per-regime MatchResult, so no "event-study table" is emitted and the driver verdict is built from the correlation grid + jackknife + scan-max only — not from the REQ-020 headline metric. The figure driver's run() renders 3 of the 4 figures its own docstring promises (regime_precision_recall.png is absent). REQ-050 requires a "regime table + event-study table + scan-max/FDR summary". Fix: wire regime_event_study() into the driver, add it to RegimeArtifacts + a committed table, and render the precision/recall figure.
  • F2 (significant) — BH-FDR grid dimensions "deseason variants" and "thresholds" are inert. In the driver grid loop the per-cell statistic is robust_corr(sub_x, sub_y) over the regime subset only; variant and threshold are recorded as labels but do not change the computed p-value. Every variant×threshold cell within a regime therefore shares an identical p_perm, so n_tests (e.g. 12) is padded with duplicate tests and BH-FDR is applied "across the grid" (REQ-031/032, AC-007) over duplicated p-values rather than genuinely distinct tests. AT7 exercises bh_fdr on synthetic p-values directly, so this gap is not caught by a test. Fix: either compute a genuinely distinct statistic per variant (switch the deseason residual) and per threshold (the event-study metric, per F1), or reduce the grid to the genuinely-distinct family and document the true n_tests. This matters for the honesty of the eventual real-data multiplicity claim.
  • F3 (minor) — 52-week secondary window not exercised. REQ-010 asks for the rolling-18-month "(and a 52-week)" correlation reported alongside; window_weeks_secondary=52 is configured but the driver runs a single window (windows=(window,)). Add the secondary window to the reported outputs or record an explicit deferral.
  • F4 (minor) — EDGE-004 cloud-gap honesty untested. Asserted as inherited from the reused coverage screen; acceptable, but there is no dedicated test that a cloud-gapped curtailment surfaces as an honest missed recall. Consider a small fixture, or record the inheritance explicitly.

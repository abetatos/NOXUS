Q1 Curtailment-calendar sourcing, coverage and date-granularity (central feasibility risk) Non-blocking
Question
Can a public/free, dated, source-cited Tangshan/Hebei steel curtailment calendar actually be assembled over the TROPOMI era (2019-01 → present)? From which sources (MEE / Hebei DEE / Tangshan municipal notices, CREA / Custeel / Mysteel public reports, reputable news, official holiday calendars), and at what date granularity (day / week / month / season)? Specifically: are there ≥1 securely-dated event in the 2023-peak window and ≥1 in 2024 to support the event-bound test?
Why it matters
This is the same class of risk as the NOX-007 (GEMS) and NOX-011 (VIIRS) T1 spikes: the whole event-level attribution (REQ-021) depends on it. A rich event-level calendar enables the "few large events drive the 2023 peak" test at event granularity; a coarse-only calendar reduces it to heating-season edges + holidays with less power.
Blocking
No (becomes blocking only in the T1 NO-GO branch — heating seasons not even datable — which escalates to the developer)
Default assumption if not answered
Run the T1 assembly spike (REQ-001) to record what is securely datable and a go/no-go verdict; then build from the coarse floor (heating-season restriction windows + Golden Week + Spring Festival + any securely-dated campaigns), mark provenance + granularity + confidence per event, and expand opportunistically. Report reduced power at coarse granularity (EDGE-001). This lets the task reach spec_ready and proceed. (A3)

Q4 Regime-boundary definition (fixed calendar split vs data-driven change-point) Non-blocking
Question
How should the "2023 regime" and "2024 collapse" boundaries be fixed: a rolling-peak-centred window + fixed calendar-year split, or a data-driven change-point on the rolling-correlation series? A data-driven boundary risks being tuned to CREA.
Why it matters
Determines the anti-p-hacking posture of the segmentation. A boundary optimised against CREA would manufacture the within-regime peak.
Blocking
No
Default assumption if not answered
Use a fixed pre-registered rule (rolling-peak-centred 18-month window for the 2023 regime + a fixed calendar-year split for 2024), declared before viewing outcomes, and report a boundary-robustness sweep; never optimise the boundary against CREA (A5, NFR-005, ERR-004).

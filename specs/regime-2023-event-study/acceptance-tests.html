Purpose

This document defines acceptance-level test scenarios for NOX-012.

These describe the observable behaviour that must be true for the feature to be accepted. They map back to the REQ/NFR/EDGE/ERR/AC IDs in requirements.html.

  • The implementer should use this file to create or update automated tests.
  • The reviewer should use this file to verify that the implementation satisfies the approved spec.

Test strategy

The acceptance tests must verify:

  • the T1 feasibility gate (coverage/provenance report + go/no-go) and the calendar's compatibility with the unchanged NOX-004 loader;
  • rolling-regime identification on a planted-regime synthetic (peak recovered; rule not CREA-tuned);
  • the event-bound jackknife (attributes a peak to a few large events; does not on a continuous fixture);
  • the regime-conditioned match reusing NOX-004 (precision/recall/lead, not r);
  • the scan-maximum null (holds FP near α on AR(1); planted peak beyond band) and BH-FDR multiplicity;
  • the no-look-ahead guard (reused);
  • the honest-null path (artefact verdict is a valid PASS);
  • error cases (missing inputs; malformed/absent calendar; too-few-events; anti-p-hacking refusal);
  • non-regression of existing catalyst/validation/signal/CLI behaviour.

Testing style configured for this project

pytest with synthetic, seeded fixtures (deterministic, no network/credentials), mirroring the NOX-004 / NOX-008 / NOX-009 style: a planted-regime generator (coupling switched on in one window), an event-bound vs continuous variant, independent AR(1) null series, a small fixture calendar CSV. Source probing (T1) is mocked; no live web fetch at test time. The real-data run on the committed cube + assembled calendar is a separate, opt-in task (T12), not a unit test.

uv run pytest
uv run ruff check .

Acceptance tests

AT1 T1 feasibility spike: coverage/provenance report + go/no-go verdict Draft
Related requirements
REQ-001, EDGE-001, AC-001
Scenario
probe_sources surveys (mocked) candidate sources and classifies coverage.
Preconditions
Mocked source responses spanning the TROPOMI era with mixed granularity/confidence; no network.
Action
Run noxus assemble-calendar --probe.
Expected result
A coverage-and-provenance report is produced (per candidate: source, date, granularity, direction, securely-dated flag) plus a go/no-go verdict (GO-event-level | GO-coarse-floor | NO-GO); a SOURCES.md-style artefact is written; the verdict is recorded before the build proceeds.
Negative expectations
No event is invented; NO-GO is surfaced as an escalation, not a silent stop.
Suggested test location
tests/catalyst/test_calendar.py
AT2 Calendar assembled with provenance; loads through the unchanged NOX-004 loader Draft
Related requirements
REQ-002, REQ-003, REQ-004, AC-002
Scenario
A fixture calendar with start,end,direction,cause + provenance columns, including one unsourced row.
Preconditions
Fixture CSV; the variance/regime module and the existing load_curtailment_calendar importable.
Action
Run validate_calendar, then load via noxus.catalyst.groundtruth.load_curtailment_calendar.
Expected result
Sourced events pass; the unsourced row is excluded/flagged (never fabricated); the CSV loads cleanly through the unchanged loader (four-column contract), provenance columns ignored.
Negative expectations
No modification to groundtruth.py; no unsourced event silently kept.
Suggested test location
tests/catalyst/test_calendar.py
AT3 Planted-regime: rolling-correlation identification recovers the peak; rule not CREA-tuned Draft
Related requirements
REQ-010, REQ-011, NFR-005, AC-003
Scenario
A synthetic residual+benchmark with a coupling switched on in one 18-month window and near-zero elsewhere.
Preconditions
Planted-regime generator; fixed seed.
Action
Run rolling_regime and the fixed segmentation rule.
Expected result
The peak window is recovered; each regime is scored with robust_corr (autocorrelation-robust CIs); the segmentation function exposes no CREA-agreement/optimisation argument and is seed/order-stable.
Negative expectations
The boundary is not chosen to maximise r; no benchmark-tuning parameter exists.
Suggested test location
tests/catalyst/test_regime.py
AT4 Event-bound jackknife attributes (or not) the peak to a few large events Draft
Related requirements
REQ-021, AC-004
Scenario
Two fixtures: (a) a regime correlation created by a few large step events; (b) a broadly-distributed continuous coupling.
Preconditions
Event-bound and continuous generators; fixed seed.
Action
Run event_bound_jackknife (leave-one-large-event-out) on each.
Expected result
(a) removing the few large events collapses the peak r (attributed as event-bound); (b) no single event dominates (attributed as continuous). The per-event contribution to the peak is reported.
Negative expectations
The verdict is not asserted independent of the jackknife result.
Suggested test location
tests/catalyst/test_regime.py
AT5 Regime-conditioned match reuses NOX-004; precision/recall/lead per regime (not r) Draft
Related requirements
REQ-020, AC-005
Scenario
Planted NO₂ events + a planted calendar/BF-jump set within a regime.
Preconditions
Fixtures; the NOX-004 detect_events/production_events/match_events importable.
Action
Run regime_event_study.
Expected result
Precision / recall / FDR / signed lead with CIs are computed per regime by reusing the NOX-004 primitives; the headline is an event-study metric, not a Pearson r; heating-season intervals are edge-matched (EDGE-002).
Negative expectations
No re-implementation of detection/matching; recall not inflated by counting every period inside a blanket interval.
Suggested test location
tests/catalyst/test_regime.py
AT6 Scan-maximum null: FP near α on AR(1); planted peak beyond the band Draft
Related requirements
REQ-030, EDGE-005, AC-006
Scenario
(a) Two independent strongly-autocorrelated AR(1) series; (b) the planted-regime fixture from AT3.
Preconditions
Fixed seeds; block length from the reused NOX-008 rule; reduced draw count for test speed.
Action
Run scan_max_null (block-permutation MAX-rolling-r distribution).
Expected result
(a) the observed scan-max r falls inside the null band at the configured α across seeds (a genuinely-null series does not routinely yield a "significant" peak); (b) the planted peak's percentile is beyond the null band. The block length and effective window count are recorded.
Negative expectations
The naïve "one window hit 0.76" claim is never reported without this null; the null does not use an i.i.d. shuffle that destroys autocorrelation.
Suggested test location
tests/catalyst/test_regime.py
AT7 Multiplicity: fixed grid, n_tests recorded, BH-FDR applied Draft
Related requirements
REQ-031, REQ-032, AC-007
Scenario
The test grid (variants × windows × thresholds × regimes) is enumerated before outcomes; a family of p-values is corrected.
Preconditions
A grid whose p-values include one nominally-significant cell that should not survive FDR.
Action
Run the driver's grid + bh_fdr.
Expected result
n_tests equals the enumerated grid size; BH-FDR matches a reference; the lone favourable cell not surviving FDR is reported as non-significant.
Negative expectations
The grid is not expanded after viewing outcomes; no cell reported significant on its naïve p alone.
Suggested test location
tests/catalyst/test_regime.py
AT8 No-look-ahead guard (reused) Draft
Related requirements
REQ-040, NFR-003, AC-008
Scenario
Detection at time t and any lead-vs-publication window must be causal.
Preconditions
A residual fixture; the NOX-004 causal detector reused.
Action
Compute detection at t, then append future data and recompute; inspect the lead-vs-publication window construction.
Expected result
Detection at t is unchanged by appended future data; the lead window uses only information available at the decision time (incl. processing latency); regime identification is labelled descriptive (not predictive) in the output.
Negative expectations
No future data enters a baseline; regime identification is not presented as a forward-predictive claim.
Suggested test location
tests/catalyst/test_regime.py
AT9 Honest-null path: "multiple-comparisons artefact" verdict is a valid PASS Draft
Related requirements
REQ-032, NFR-004, AC-009
Scenario
A null fixture where the scan-max null shows the peak is unsurprising and/or FDR wipes out the event matches.
Preconditions
AR(1) null residual+benchmark; fixed seed.
Action
Run the full driver and read the verdict.
Expected result
The report concludes "2023 peak consistent with a multiple-comparisons artefact of the rolling window"; the pipeline treats this as a completed, valid outcome (PASS), not an error or a failure.
Negative expectations
A null is not worded as a failure; the pipeline does not keep searching for a favourable window.
Suggested test location
tests/catalyst/test_regime.py

Edge case tests

AT-EDGE-1 Coarse-only calendar fallback; low-power regime labelled Draft
Related requirements
EDGE-001, EDGE-003, ERR-003
Scenario
T1 yields only the coarse floor (heating-season windows + holidays); one regime has very few events.
Preconditions
A coarse fixture calendar; a sparse-event regime.
Action
Run the study on the coarse calendar.
Expected result
The study proceeds at coarse granularity; the event-bound test is labelled reduced-power; the sparse regime is labelled low-power with wide CIs, not omitted; the event-level jackknife is refused below the minimum (ERR-003) and falls back to coarse.
Negative expectations
The task does not block on a thin calendar; unstable rates are not emitted as if stable.
Suggested test location
tests/catalyst/test_regime.py
AT-EDGE-2 2024-collapse dual diagnostic; no forced verdict when ambiguous Draft
Related requirements
REQ-022, EDGE-006

A fixture where both a calendar-cadence change and an intensity-decoupling shift are present in 2024.
Preconditions
A calendar with a changed 2024 cadence + a NOX-003.1 secular-trend fixture.
Action
Run collapse_attribution.
Expected result
Both diagnostics are reported side by side; when both fit, the output states the attribution is not identifiable from this data rather than forcing one cause.
Negative expectations
No single cause is asserted when both are consistent.

Error case tests

AT-ERR-1 Missing residual/benchmark; malformed/absent calendar Draft
Related requirements
ERR-001, ERR-002
Scenario
(a) the NOX-003.1 residual or CREA benchmark absent; (b) a calendar CSV missing start/end/direction; (c) the calendar path absent.
Preconditions
Temp working dir missing the respective artefact / a malformed fixture CSV.
Action
Invoke noxus regime-study in each condition.
Expected result
(a) fails naming the producing command; (b) the existing loader raises the actionable ValueError; (c) the study degrades to BF-rate-jumps-only with a recorded note (reuses NOX-004), not fabricated dates.
Negative expectations
No silent degradation presented as a full result; no invented calendar events.
Suggested test location
tests/cli/test_regime_cli.py, tests/catalyst/test_calendar.py
AT-ERR-2 Anti-p-hacking refusal: no CREA-agreement objective on the estimators Draft
Related requirements
ERR-004, NFR-005, ERR-003
Scenario
A caller attempts to make regime segmentation / the null estimator select a boundary or threshold by maximising CREA agreement; and the event-level jackknife is requested below the minimum event count.
Preconditions
The regime module importable; a sparse-event fixture.
Action
Inspect the estimator signatures for any CREA-agreement/optimisation parameter; request the event-level jackknife with too few events.
Expected result
The estimators expose no such parameter (the runtime face of NFR-005); the event-level jackknife is refused below the configured minimum and the study falls back to coarse with a recorded note (ERR-003).
Negative expectations
No hidden keyword tunes a boundary/threshold against CREA; no unstable jackknife emitted below the minimum.
Suggested test location
tests/catalyst/test_regime.py

Technical summary

Two small new modules plus a thin orchestration layer, built on top of the NOX-004 catalyst and NOX-008 robust-significance machinery — not parallel to them.

  1. Calendar assembly (noxus/catalyst/calendar.py, new): a probe_sources() T1 feasibility spike (coverage + provenance report + go/no-go), and assemble_calendar() / validate_calendar() that curate the dated, source-cited tangshan_hebei_curtailment.csv. Output conforms to the existing load_curtailment_calendar schema (start,end,direction,cause) with extra provenance columns the loader tolerates — so NOX-004 code is untouched.
  2. Regime study (noxus/catalyst/regime.py, new): (a) rolling_regime() — recompute the rolling-18-month / 52-week NO₂↔CREA correlation (reuse validation.preprocess/leadlag), locate the 2023 peak + 2024 collapse, segment by a fixed rule, score each regime with robust_corr; (b) regime_event_study() — reuse detect_events + production_events + match_events per regime; (c) event_bound_jackknife() — leave-one-large-event-out on the 2023 regime; (d) collapse_attribution() — the 2024 dual diagnostic (calendar-cadence change vs NOX-003.1 secular-trend behaviour); (e) scan_max_null() — the rolling-window scan-maximum null reusing robust.py block-permutation tooling; and BH-FDR (bh_fdr) across the fixed grid.

Why this shape: the event-study primitives (detection, ground truth, matching), the curtailment-calendar loader, and the autocorrelation-robust significance are all already tested code. NOX-012 adds only the two genuinely-new pieces — a curated public calendar and a regime-conditioned orchestration with a scan-maximum null — and reuses everything else read-only. The market linkage is deliberately excluded (NOX-013/014, A1).

Test design

  • Calendar schema/provenance (AT1/AT2): a fixture CSV with + without provenance → validate_calendar accepts sourced events, rejects/flags unsourced; assemble_calendar output loads cleanly through the unchanged load_curtailment_calendar.
  • Planted regime (AT3): a synthetic residual+benchmark with a coupling switched on in one 18-month window → rolling_regime recovers the peak window; the segmentation rule is seed/order-stable and takes no CREA-tuning argument.
  • Event-bound jackknife (AT4): a fixture where the regime r is created by a few large step events → leave-one-out attributes the peak to them; a broadly-coupled fixture → jackknife shows no single-event dominance.
  • Regime match (AT5): planted NO₂ events + planted calendar/BF events → precision/recall/lead per regime recovered (reuses match_events).
  • Scan-maximum null (AT6): independent AR(1) series → the scan-max-of-rolling-r test holds false-positive near α across seeds; a planted-regime peak sits beyond the null band.
  • Multiplicity (AT7): the fixed grid records n_tests; bh_fdr across the grid matches a reference; a lone favourable cell not surviving FDR is flagged non-significant.
  • No-look-ahead guard (AT8): detection at t unchanged by appended future data; any lead-vs-publication window is causal (reuses the NOX-004 guard).
  • Honest-null path (AT9): a null fixture drives the report to the "multiple-comparisons artefact" verdict, asserted to be a PASS.
  • CLI + determinism (AT10/AT-REG-1): subcommands wired; same seed → identical tables; existing commands unchanged.

All statistics tested on synthetic, seeded fixtures; no network at test time (source probing mocked; the calendar under test is a small fixture CSV).

Risks and trade-offs

  • Calendar existence / coverage / granularity (top risk, Q1). A rich event-level public calendar may not be assemblable; like the NOX-007 (GEMS) and NOX-011 (VIIRS) T1 spikes, this is gated. Mitigation: the T1 assembly spike (REQ-001) records a go/no-go, and a safe coarse-floor default (heating-season windows + Golden Week/Spring Festival + securely-dated campaigns) lets the task proceed with reduced power (EDGE-001) — so the risk is non-blocking.
  • The 2023 peak is a rolling-window multiple-comparisons artefact (the honest-null crux). Many overlapping 18-month windows were effectively scanned; a peak of 0.76 may be unsurprising under the scan-maximum null. Mitigation: REQ-030's scan-max null + REQ-031's BH-FDR make this conclusion first-class and reportable (AC-009).
  • Look-ahead leakage. Regime identification is in-sample/descriptive; only the exogenous-curtailment event study and causal detection support any timing claim. Mitigation: causal baselines (reused) + grid fixed before outcomes + a guard test (REQ-040); the report labels regime identification as descriptive, not predictive.
  • Anti-p-hacking on regime boundaries. Choosing the boundary that maximises r would manufacture the result. Mitigation: a fixed pre-registered rule (REQ-011, Q4); estimators take no CREA-agreement objective (ERR-004); a boundary-robustness sweep is reported.
  • Few events / low power per regime. Sub-period samples are small. Mitigation: autocorrelation-robust CIs widen honestly; low-power segments labelled (EDGE-003); event-level jackknife refused below a minimum (ERR-003).
  • Cloud-gapped curtailments. A real curtailment hidden by cloud lowers recall honestly (EDGE-004), not silently absorbed.
  • Deep-review category. This task is not in a high-risk category (no auth/payments/migrations/infra); it is analysis on existing data + a public calendar. Standard review applies; the emphasis is the no-look-ahead + multiple-testing + anti-p-hacking disciplines above.
  • Rejected: re-implementing event detection / matching / robust significance (they exist and are tested — reuse); a paywalled curtailment dataset (public/free only, NFR-002); selecting the regime boundary or window against CREA (p-hacking).

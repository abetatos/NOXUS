Technical summary

The NOX-009 decomposition already separates series construction from partitioning: _level_series_for_cube() builds the footprint/ring/meteo level series, and decompose_from_levels() partitions them. The ring radii are currently read from a freshly constructed SignalConfig() inside _level_series_for_cube, which is what makes them un-sweepable.

The change is therefore small and structural: lift the ring radii out of the hard-coded SignalConfig() and into the sweep config, defaulting to the present values, then loop the existing decomposition over a ring grid. No estimator, mask or partition algorithm is edited. The new surface is one module, one config dataclass and one CLI subcommand, mirroring how NOX-008's scale-sweep wraps the same machinery over an AOI/resolution grid.

Design constraint that decides the shape: the current default must keep producing byte-identical output (NFR-003). That rules out changing _level_series_for_cube's signature incompatibly; the ring parameter is added as an optional argument whose None default preserves the existing SignalConfig lookup exactly.

Data flow

The only new node in the graph is the ring grid. Everything downstream is existing code called in a loop.

Test design

IDTestMethod
AT1Ring grid swept; advection flag correctRun on a small synthetic cube; assert one row per (ring × basis × res × weighting) and that beyond_advection is False only for (25,60).
AT2Benchmark-blindAssert sweep_rings has no benchmark parameter (inspect.signature) and that a monkeypatched benchmark loader is never called.
AT3Positive controlSynthetic cube with a known local source whose plume is planted inside the 25–60 km annulus. Assert the recovered local share is near zero at (25,60) and rises above the 0.05 threshold at (60,120) — i.e. the sweep can detect self-subtraction.
AT3bNegative controlSame fixture with the source confined to the footprint and no plume in the ring. Assert the local share is stable across all rings — i.e. the sweep does not manufacture a rise from geometry alone.
AT4All cells reported; raw ΔR² presentAssert no row is dropped and that dr2_local can be negative while share_steel_local is clamped, with local_clamped flagged.
AT5Octant weighting & imbalanceOn an anisotropic fixture, assert the plain and octant-weighted rows differ and the imbalance ratio is reported.
AT6Verdict ruleTable-driven: synthetic share/CI inputs ⇒ each of the three verdicts; assert the threshold is read from config and not hard-coded at the call site.
AT7Edge casesRealised radius on a truncating ring; no footprint/ring overlap; daily-vs-weekly disagreement ⇒ inconclusive.
AT-REG-1RegressionRun noxus variance and diff against the committed variance_decomposition.csv; must be identical.
AT-ERR-1Error statesEmpty ring ⇒ refused row, sweep continues; missing cube/ERA5 ⇒ the NOX-009 messages.

Risks and trade-offs

RiskLevelMitigation
The sweep overturns NOX-009 and the paper's central claimMedium likelihood, high impactThis is the purpose, not a risk to be managed away. The verdict rule is pre-registered (REQ-031) so the outcome cannot be argued after the fact, and REQ-040 requires the findings note to state explicitly that the paper needs correction.
Far-ring anisotropy masquerades as a physical effectHigh likelihood, medium impactREQ-013 octant weighting, REQ-022 reported imbalance, AT3b negative control, AT5.
Larger rings average more cells ⇒ less ring noise ⇒ partition shifts for the wrong reasonMediumEDGE-005: cell counts reported per row; octant weighting partially decouples; AT3b shows the sweep is flat when there is no plume.
Threading the ring parameter breaks the existing defaultLow likelihood, high impactring=None preserves the exact SignalConfig path; AT-REG-1 is a hard byte-comparison gate.
Ring truncation by the AOI clip is invisibleMediumEDGE-001: realised maximum radius recorded per ring.
tau = 4 h is itself an assumptionMediumThe advection scale is a marker, not a fitted quantity; the sweep spans 25→120 km so the conclusion does not depend on the exact value. Recorded in RingSweepConfig and in assumptions.html.

Rollback plan

The change is additive and file-isolated. Rollback is: revert noxus/signal/ring_sweep.py, analysis/ring_sensitivity.py, tests/signal/test_ring_sweep.py, the RingSweepConfig block and the CLI subcommand, and restore the _level_series_for_cube signature. No committed artefact is overwritten — the sweep writes ring_sensitivity.csv, never variance_decomposition.csv — so prior results survive a rollback untouched.

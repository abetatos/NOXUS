Acceptance tests

Given/When/Then. Every test names the requirement it discharges. The two controls (AT3, AT3b) are the load-bearing ones: without both, a sweep result cannot be interpreted.

Location: tests/signal/test_ring_sweep.py. Command: uv run pytest tests/signal/test_ring_sweep.py -q.

AT1 — The ring grid is swept and flagged REQ-001/002/003

Given a synthetic cube spanning ±130 km around a single facility and the default RingSweepConfig.

When sweep_rings(cfg) runs.

Then the frame has exactly len(ring_grid) × len(bases) × len(resolutions) × len(weightings) rows; beyond_advection is False for (25,60) and True for (60,100) and (60,120); background_ring is called with the swept radii (spy).

And not: SignalConfig.background_inner_km is never consulted when a ring is supplied.

AT2 — Structurally benchmark-blind NFR-001, ERR-004

Given the public API of noxus.signal.ring_sweep.

When the signature of sweep_rings is inspected and a full run executes with the CREA loader monkeypatched to raise.

Then no parameter name matches bench|crea|target|label, and the run completes without the loader ever being called.

And not: no module-level import of the benchmark path anywhere in the sweep’s import graph.

AT3 — POSITIVE CONTROL: planted in-ring plume is detected AC-004, REQ-020/021

Given a synthetic cube where a known local activity series drives (a) the footprint and (b) an advected plume deposited at 30–50 km — i.e. inside the 25–60 km annulus — on top of an independent regional common mode.

When the sweep runs.

Then the recovered cluster-local share is ≈ 0 at (25,60) and rises above self_subtraction_threshold with a CI excluding zero at (60,120); the regional share falls by a comparable amount over the same sweep (REQ-021).

And not: the verdict must be self-subtraction, not inconclusive — the rule must actually fire on the case it exists to catch.

AT3b — NEGATIVE CONTROL: geometry alone does not manufacture a rise EDGE-002/005, A3

Given the same fixture with the local source confined to the footprint and no plume in any ring.

When the sweep runs.

Then the cluster-local share is stable across all five rings (no monotone rise), the verdict is ring-robust, and the octant-weighted rows agree with the plain rows to within the bootstrap CI.

And not: a rise driven purely by larger rings averaging more cells must not appear; if it does, the sweep is not fit for purpose and T7 must not run.

AT4 — Every cell reported; raw ΔR² preserved REQ-011/012, EDGE-004

Given a fixture engineered so at least one cell yields a negative raw dr2_local.

When the sweep runs and writes the CSV.

Then that row carries the negative dr2_local, a clamped share_steel_local == 0.0, and the local_clamped flag; no row is missing.

And not: the clamped zero must never be written without the raw value beside it — the failure mode this project already shipped once.

AT5 — Octant weighting and imbalance REQ-013/022

Given a deliberately anisotropic AOI (rectangular, long in latitude) so far rings over-weight the N/S lobes.

When the sweep runs with weightings = ("plain", "octant").

Then octant_counts and octant_imbalance are populated per ring; the plain and octant rows differ measurably at the outermost ring; an empty octant is reported, not silently dropped.

AT6 — The verdict rule is mechanical REQ-030/031

Given hand-built frames encoding each branch: (i) 3 of 4 cells above threshold with CI excluding zero; (ii) all cells below threshold with CI containing zero; (iii) exactly 1 cell above threshold.

When the verdict function is applied.

Then it returns self-subtraction, ring-robust, inconclusive respectively, and changing cfg.self_subtraction_threshold changes the outcome — proving the threshold is read from config, not inlined.

And not: the verdict must not depend on any quantity derived from the benchmark.

AT7 — Edge cases EDGE-001/003/006

Given (a) a ring whose outer_km exceeds the cube extent; (b) a ring with inner_km inside the footprint radius; (c) a frame where weekly says self-subtraction and daily says ring-robust.

When the sweep / verdict runs.

Then (a) realised_max_km < requested and is recorded; (b) no cell appears in both footprint and ring masks; (c) the verdict is inconclusive and both cadences are reported.

And not: the cadence that agrees with the prior NOX-009 result must not be preferred.

AT-REG-1 — REGRESSION: the existing decomposition is untouched NFR-003

Given the committed data/derived/variance_decomposition.csv.

When noxus variance is run with no new flags after the ring=None threading.

Then the output is identical to the committed file (exact string comparison of the CSV).

And not: no tolerance is allowed here. Any drift means the ring threading changed the default path and the sweep’s baseline row would no longer be the NOX-009 result.

AT-ERR-1 — Error states ERR-001/002/003

Given (a) a ring grid entry producing zero cells; (b) an absent weekly cube; (c) an absent daily cube with "D" requested; (d) an absent ERA5 snapshot.

When the sweep runs.

Then (a) that ring is recorded as refused with its cell count and the sweep continues; (b)–(d) raise the existing NOX-009 messages naming the command to run.

Pre-review checklist

  • AT-REG-1 passed before and after the variance.py change.
  • AT3 and AT3b both green — the sweep detects real self-subtraction and does not invent it.
  • Verdict threshold unchanged since before T7 ran (check git history of RingSweepConfig).
  • uv run pytest and uv run ruff check . clean.

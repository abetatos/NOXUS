Requirements — Pipeline positive control (does the pipeline recover a signal it should?)

Task ID NOX-021
Feature slug pipeline-positive-control
Status spec_ready
Author spec-author
Human approvalpending
Origin Paper critique B1 (2026-08-31): NOX-016 returned pipeline-suspect and nothing in the study can currently discharge it.

Summary

NOX-016 (scale contrast) returned the verdict pipeline-suspect: the benchmark-blind NO2 features track national steel activity no better than they track Tangshan's own rate, which is the opposite of what the paper's spatial explanation predicts. That verdict cannot currently be discharged, because the study has never demonstrated that its pipeline recovers any signal at all. Every result is a null, so a broken feature path and a genuinely absent steel signal are observationally identical. This task supplies the missing positive control: run the identical footprint-minus-ring pipeline against NO2 perturbations over the same AOI that are large, externally documented and not in dispute. If the pipeline recovers them, the null becomes a statement about the steel signal; if it does not, the paper's central claim is not interpretable and must be withdrawn.

Functional requirements

REQ-001When the positive control runs, the system shall score the committed weekly and daily footprint-minus-ring series against a fixed, pre-registered set of externally documented NO2 perturbation windows over the Tangshan AOI, using the same deseasonalisation, meteorological control and robust-inference stack as Section 6 of the paper.
REQ-002The pre-registered event set shall be, and shall be fixed in code before any effect size is computed: (a) the COVID-19 control period 2020-02-01 to 2020-03-15; (b) the annual Spring Festival window, day-of-year aligned, 2019–2026; (c) the 2022 Winter Olympics air-quality control period 2022-01-30 to 2022-02-20; (d) the annual heating-season restriction windows already sourced in the 21-event curtailment calendar.
REQ-003For each event the system shall report the standardised mean shift of the footprint series inside the window against a matched out-of-window baseline, its moving-block bootstrap 95% CI, a block-permutation p, and the same statistics for the background ring series so that a regional-only response is distinguishable from a footprint-specific one.
REQ-004The system shall emit a three-way verdict under a rule fixed before the run: pipeline-valid when the COVID window (a) is recovered with the correct sign at block-permutation p < 0.05 and a CI excluding zero; pipeline-degraded when (a) is recovered with correct sign but not significantly, while at least two of (b)–(d) are; pipeline-suspect otherwise.
REQ-005The system shall write a committed artefact data/derived/pipeline_positive_control.csv plus a human-readable .txt summary, following the convention of the existing sweep artefacts.
REQ-006The run shall be blind to the CREA benchmark: no CREA series may be read anywhere in the feature or scoring path.

Non-functional requirements

NFR-001Reuses the committed cube and the committed derived series. No new data acquisition, no network access, no credentials.
NFR-002All stochastic procedures use the project seed 20260712 with 5,000 bootstrap and permutation draws, matching every other analysis in the paper.
NFR-003Runtime under two minutes on the committed artefacts, so the control can be re-run as a regression check on any future pipeline change.

Edge cases

EDGE-001A pre-registered window falling in a period with no QA-valid coverage — report the window as refused with its reason and exclude it from the quorum, never silently drop it.
EDGE-002The Spring Festival window moves by up to three weeks in the Gregorian calendar; alignment is by the published lunar date per year, fixed in a committed table, not by a fixed day-of-year.
EDGE-003The COVID window overlaps the 2020 Spring Festival. Both are reported, and the rule keys on (a) alone precisely because the two cannot be disentangled; the overlap is stated in the artefact rather than corrected for.

Error states

ERR-001If the committed footprint series is absent, refuse with a message naming the missing parquet. Never regenerate it as a side effect of this task.
ERR-002If any CREA series is opened anywhere in the feature path, abort: the blindness guarantee is structural, not advisory.
ERR-003If the verdict is pipeline-suspect, stop and escalate to the developer per ERR-002. That outcome invalidates the paper's central interpretation and is not a result to write up unattended.

Acceptance criteria

AC-001The three-way verdict, the per-event effect sizes and the footprint-versus-ring contrast are all present in the committed artefact.
AC-002The verdict rule is readable in noxus/config/run.py as compiled-in constants, with its introducing commit predating the first scoring run.
AC-003The paper gains a subsection reporting the verdict, and Section 8.2 (scale contrast) cross-references it, because pipeline-valid is what converts NOX-016's pipeline-suspect into a statement about scale rather than about correctness.
AC-004Every existing test still passes and the new module carries unit tests for the verdict rule at each of its three branches.

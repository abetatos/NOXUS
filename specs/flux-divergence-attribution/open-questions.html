Q1 Exact free raw-L2 __NO2___ swath access path (OData vs S3; read path) Non-blocking
Question
What is the exact free/public route to the raw L2 S5P_*_L2__NO2___ swath (native footprints, averaging kernel, geolocation) needed for fine oversampling — CDSE OData catalogue (Bearer token) or the S3 eodata endpoint — and does the per-variable read path match what NOX-002a's gridded openEO product exposed? NOX-002a delivered only the gridded product, so this raw path is new.
Why it matters
The whole method depends on native-footprint L2; getting a paid/licence-gated path would violate the core public-free principle (the NOX-011 VNF lesson).
Blocking
No — verified at T1 before the full fetch.

Q2 Proceed given the known method-hardness and the heavy compute cost? Non-blocking
Question
Flux-divergence is known to resolve poorly in high-background/complex-wind NE China (task definition), so a NO-GO honest null is realistic; and fine oversampling + divergence over a multi-year raw swath is compute/storage-heavy (a few tens of GB raw; server-class full run). Does the developer want to invest in the full build now, or run only the bounded-subset T1 gate first and decide on evidence?
Why it matters
Balances the decisive value of even a null (closes DL-A) against the effort/cost of a method with a real chance of not resolving here.
Blocking
No — the spec is coherent either way; this is a go/no-go judgement for the developer.
Default assumption if not answered
Proceed, but let the T1 feasibility gate decide on evidence on a bounded subset (laptop-feasible): GO/GO-degraded only if a coherent localised source term co-locates with the plants above noise; else NO-GO honest null and stop (ERR-002). No full-record download or full build before a GO (assumptions A7, and the compute profile, NFR-008).
Affected files / sections
requirements.html (honest feasibility caveat, REQ-014/015), design.html (compute profile, risks), tasks.html (T1)

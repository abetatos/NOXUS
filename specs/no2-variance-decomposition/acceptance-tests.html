Purpose

This document defines acceptance-level test scenarios for NOX-009.

These describe the observable behaviour that must be true for the feature to be accepted. They map back to the REQ/NFR/EDGE/ERR/AC IDs in requirements.html.

  • The implementer should use this file to create or update automated tests.
  • The reviewer should use this file to verify that the implementation satisfies the approved spec.

Test strategy

The acceptance tests must verify:

  • the main success scenario (a four-term variance budget is produced on both change bases at both resolutions);
  • the anti-p-hacking invariant (no benchmark ever enters the estimator);
  • quantitative recovery on a planted-decomposition synthetic;
  • autocorrelation-aware CIs (block bootstrap wider than i.i.d.);
  • edge cases (order-dependence, negative ΔR² clamp, gap-aware daily differencing);
  • error cases (missing cube / ERA5, benchmark refusal);
  • non-regression of existing signal/attribution/validation/CLI behaviour.

Testing style configured for this project

pytest with synthetic fixtures (deterministic, no network/credentials), mirroring the NOX-003.1 / NOX-008 test style: a planted-signal generator with known variance shares; a fake/xarray cube fixture; fixed RNG seeds. In-repo real-data smoke on the committed cube is a separate, opt-in task, not a unit test.

uv run ruff check .

Acceptance tests

AT1 Series built via existing attribution + meteo/deseason reuse Draft
Related requirements
REQ-001, REQ-002
Scenario
The decomposition constructs its footprint (5 km) and background-ring (25–60 km) series and its meteo-normalised / deseasonalised inputs by calling the existing attribution + noxus.signal.index/intensity pathways, not a re-implementation.
Preconditions
A small synthetic cube fixture with a footprint region, a background ring, and injected meteo covariates.
Action
Invoke the series-construction step of the decomposition on the fixture.
Expected result
The produced footprint / background / meteo-normalised series equal those from the existing modules on the same fixture (byte-for-byte / within float tolerance); no attribution or index algorithm is altered.
Negative expectations
No new footprint/background/deseason algorithm is introduced; existing functions are not modified.
Suggested test location
tests/signal/test_variance.py
AT2 Anti-p-hacking: estimator takes no benchmark argument and never reads CREA Draft
Related requirements
REQ-003, NFR-001, AC-002
Scenario
The core decomposition function's signature is inspected and the module's imports/reads are checked; the benchmark cannot influence any share.
Preconditions
The variance module is importable.
Action
Use inspect.signature on the core estimator; scan the module for any import/read of the CREA benchmark path or a benchmark parameter (mirrors the NOX-003.1 fit_intensity_trend guard).
Expected result
The estimator exposes no benchmark/output parameter; the module never imports or opens the CREA parquet/CSV; the guard test passes.
Negative expectations
No hidden keyword accepts a benchmark; no smoothing/threshold/df is selectable against CREA.
Suggested test location
tests/signal/test_variance.py
AT3 Planted-decomposition shares recovered; ΔR² order recorded Draft
Related requirements
REQ-020, REQ-021, EDGE-001, AC-001
Scenario
A synthetic change signal is built as footprint_change = regional + β·meteo + local + noise with known variance shares.
Preconditions
Planted-signal generator with configurable, known shares and low cross-term collinearity; fixed seed.
Action
Run the nested-model partition (regional → +meteo → +local → noise).
Expected result
The four recovered shares match the planted shares within tolerance and sum to ≈ 1; the entry order and per-step ΔR² are recorded in the output.
Negative expectations
Shares are not silently renormalised to hide a mismatch; the order is not chosen to maximise the steel-local share.
Suggested test location
tests/signal/test_variance.py
AT4 Both change bases × both resolutions, one table row each Draft
Related requirements
REQ-010, REQ-011, REQ-022, AC-003
Scenario
The budget is produced on first differences and on the deseasonalised residual, at weekly and daily resolution.
Preconditions
Weekly and daily cube fixtures available.
Action
Run the full decomposition; read the emitted variance-partition CSV.
Expected result
Four rows (2 bases × 2 resolutions), each carrying n, the four shares, the entry-order ΔR² terms, and the headline steel-local share.
Negative expectations
No basis/resolution is omitted from the table; levels are not used as a "change" basis.
Suggested test location
tests/signal/test_variance.py, tests/cli/test_variance_cli.py
AT5 Change-detector ceiling contrasted with the level ceiling; verdict stated Draft
Related requirements
REQ-030, REQ-031, AC-004
Scenario
From the steel-local share f, the implied change ceiling ≈ sqrt(f) is reported and compared with the level ceiling ≈ sqrt(attributable_cap).
Preconditions
A budget with a known steel-local share; attributable_cap = [0.30, 0.43] from config.
Action
Compute the ceiling comparison and the physical-vs-method-bound verdict.
Expected result
The output states both ceilings numerically and a verdict: ceiling-bound/physical if change share ≈ level share, headroom/method-bound if change share ≫ level share; the observed near-null (weekly r≈0.07) is framed against the ceiling.
Negative expectations
No verdict is asserted independent of the measured shares; the sqrt-independence assumption is stated, not hidden.
Suggested test location
tests/signal/test_variance.py
AT6 Moving-block bootstrap CI wider than naïve on an autocorrelated fixture Draft
Related requirements
REQ-040, NFR-002, AC-005
Scenario
On an AR(1)-autocorrelated fixture, the CI on the steel-local share is computed both by moving-block bootstrap and by naïve i.i.d. resampling.
Preconditions
Fixture with strong positive serial correlation; fixed seed; block length from the reused NOX-008 rule.
Action
Compute both CIs via noxus.validation.robust.
Expected result
The block-bootstrap CI is strictly wider than the i.i.d. CI; both are reported; the block length used is recorded.
Negative expectations
The naïve CI is never reported alone; the seed is not left unset.
Suggested test location
tests/signal/test_variance.py
AT7 Figures + findings note; honest verdict; no cherry-picking Draft
Related requirements
REQ-050, REQ-051, NFR-003, AC-007
Scenario
The run emits a stacked variance-partition figure (regional/meteo/steel-local/noise per basis×resolution), a ceiling-comparison figure, and a findings note.
Preconditions
A completed budget over all four cells.
Action
Generate the report artefacts.
Expected result
All four cells appear in the figure; the findings note states the physical-vs-method-bound verdict and its implication for NOX-010/011; a confirmed ceiling is worded as a valid finding.
Negative expectations
No basis/resolution is dropped to flatter the conclusion; a null is not worded as a failure.
Suggested test location
tests/signal/test_variance.py (artefact presence + content assertions)

Edge case tests

AT-EDGE-1 Negative incremental ΔR² is clamped and flagged Draft
Related requirements
EDGE-002, AC-006
Scenario
A fixture where adding a term yields a small negative ΔR² (suppression / sampling noise).
Preconditions
Planted signal tuned so one incremental step is slightly negative.
Action
Run the partition.
Expected result
The reported share for that term is clamped to 0, the raw ΔR² is recorded, and the term is flagged; no negative variance share is emitted.
Negative expectations
The pipeline does not crash; the negative value is not silently propagated.
Suggested test location
tests/signal/test_variance.py
AT-EDGE-2 Gap-aware daily first differencing records effective n Draft
Related requirements
EDGE-003, AC-006
Scenario
A daily fixture with cloud gaps; first differences must only be taken across genuine adjacent observations.
Preconditions
Daily series fixture with missing days.
Action
Run the first-difference basis at daily resolution.
Expected result
No difference is computed across a gap; no interpolation is introduced; the effective n after gap-aware differencing is recorded; a too-sparse basis is labelled low-power, not crashed.
Negative expectations
No interpolation across gaps; no silent inflation of n.
Suggested test location
tests/signal/test_variance.py
AT-EDGE-3 Degenerate background / missing meteo / near-zero local share Draft
Related requirements
EDGE-004, EDGE-005, EDGE-006
Scenario
Three sub-cases: (a) an empty/near-empty background ring at some period; (b) a meteo covariate missing for part of the series; (c) a steel-local share whose CI includes ~0.
Preconditions
Fixtures exercising each degeneracy.
Action
Run the decomposition on each.
Expected result
(a) reuses the attribution GeometryError handling and reports the budget without the regional split, labelled; (b) fits meteo on jointly-available rows and records the covered fraction, no extrapolation; (c) the implied ceiling collapses toward 0 and the report states the null is SNR-bound rather than quoting a spuriously precise tiny ceiling.
Negative expectations
No crash; no fabricated regional/meteo split; no over-precise near-zero ceiling.
Suggested test location
tests/signal/test_variance.py

Error case tests

Related requirements
ERR-004, NFR-001
Scenario
A caller attempts to pass a benchmark/output series into the decomposition estimator.
Preconditions
The variance module is importable.
Action
Attempt to call the estimator with a benchmark keyword/positional argument.
Expected result
The call fails (the estimator exposes no such parameter — TypeError), the runtime face of NFR-001.
Negative expectations
No hidden path accepts and uses a benchmark.
Suggested test location
tests/signal/test_variance.py

Expected result

Manual acceptance checklist

Use during human review.

  • All requirements have at least one acceptance test.
  • Main success path (four-cell budget + ceiling) is covered.
  • Anti-p-hacking guard (no benchmark argument) is covered.
  • Autocorrelation-aware CI (block vs i.i.d.) is covered.
  • Edge cases (order-dependence, ΔR² clamp, gap-aware n) are covered.
  • Error cases (missing cube/ERA5, benchmark refusal) are covered.
  • Non-goals (existing behaviour) are protected.
  • Tests are feasible with the current project test setup.
  • No acceptance test depends on hidden assumptions.
  • Any unresolved behavior is listed in open-questions.html.

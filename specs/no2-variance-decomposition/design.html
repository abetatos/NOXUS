Technical summary

One small reusable module plus a thin orchestration layer, in the shape of NOX-008. The core is a new noxus/signal/variance.py: a benchmark-blind hierarchical variance-partition estimator that takes the footprint (5 km) and background-ring (25–60 km) change series and the ERA5 meteo covariates, and returns a four-way budget — regional / meteo / steel-local / noise — via a sequential nested-R² decomposition. The nested models are:

Δfootprint ~ Δbackground                     → R²_regional          (a)
Δfootprint ~ Δbackground + meteo             → ΔR²_meteo            (b) incremental
Δfootprint ~ Δbackground + meteo + local*    → ΔR²_steel_local      (c) incremental
residual variance                            → 1 − R²_full          (d) noise
       (* local = the footprint's own structure orthogonal to background+meteo,
          i.e. the footprint-minus-background contrast's explainable part)

Each incremental step's ΔR² is the variance share attributed to that term; the four shares sum to 1 (within rounding). The steel-local share f is the headline: its square root is the implied SNR ceiling for a change detector, reported against the imported level ceiling ≈ sqrt(attributable_cap) = sqrt([0.30, 0.43]). The budget is computed on two change bases (first differences; deseasonalised residual) at two resolutions (weekly cube; NOX-006 daily cube), and every share/ceiling carries a moving-block-bootstrap CI reusing noxus/validation/robust.py (NOX-008).

Why this shape: the decomposition is a property of the NO₂ + meteo + background data alone, so it lives in noxus/signal/ beside intensity.py, reuses the attribution/meteo/deseason pathways read-only, and — like NOX-003.1 fit_intensity_trend — exposes no benchmark argument so p-hacking against CREA is structurally impossible. The autocorrelation-robust CI is the load-bearing reuse of NOX-008; the orchestration (driver + CLI verb + figure script) mirrors the scale-sweep wiring exactly.

Test design

  • Planted decomposition (AT3): build Δfootprint = regional + β·meteo + local + noise with known variance shares → partition_change_variance recovers the four shares within tolerance; they sum to ≈ 1; ΔR² entry order recorded.
  • Anti-p-hacking guard (AT2): inspect.signature(partition_change_variance) has no benchmark parameter; the module does not import noxus.data.benchmark nor read the CREA parquet (mirrors NOX-003.1 discipline).
  • Bases × resolutions (AT4): a small synthetic (weekly + daily) fixture → the driver emits one row per (first-diff/deseason × W/D); gap-aware first differencing records the effective n (EDGE-003).
  • Ceiling (AT5): from a known steel-local share, implied_change_ceiling = sqrt(f); level_ceiling = sqrt([0.30,0.43]); the verdict string reflects headroom vs ceiling-bound.
  • Robust CI (AT6): on an autocorrelated fixture, the moving-block-bootstrap CI on the steel-local share is wider than the naïve i.i.d. interval; negative ΔR² clamps to 0 with the raw value recorded (EDGE-002).
  • Determinism + additive (AT7/AT8): same seed/config → identical table; existing signal/attribution/validation/CLI unchanged; tests + lint pass.
  • Error states (AT-ERR-1): missing weekly cube → names noxus grid; daily requested but daily cube absent → names the NOX-006 command; missing ERA5 → names ERA5 ingest; benchmark refusal (no such parameter).

All statistics tested on synthetic fixtures (deterministic, seeded, no network). Bootstrap draws are reduced in tests for speed while asserting the width behaviour. The real decomposition on the committed cubes is run once as a validation task (AT7 narrative), not asserted numerically in CI.

Risks and trade-offs

  • Order-dependence of the nested partition (central method risk). When regional, meteo and local share variance, the sequential ΔR² attribution depends on entry order. Mitigation: fix and record the order (regional → meteo → local, REQ-021, A2); state that a commonality/Shapley split would redistribute the shared part; never pick the order that flatters the steel-local share. This is the deep-review focus item, though the task is not in a high-risk category (no auth/payments/migrations/infra/public API).
  • Estimator choice is reversible. Sequential nested-R² is the default; a Shapley/commonality decomposition or a variance-components (mixed-model) estimator are alternatives. Recorded as assumption A1 / non-blocking open question Q1; the default is defensible and cheap.
  • "Local structured" vs "noise" boundary. The steel-local term is the footprint's structure orthogonal to background+meteo; distinguishing genuine local structure from retrieval noise leans on the model. Mitigation: report the raw ΔR², the clamp (EDGE-002), and the CI; do not over-claim a tiny local share (EDGE-006).
  • Low power at daily / after gaps. Gap-aware differencing shrinks n; the block-bootstrap CI will (correctly) widen. That is the honest point, not a bug (NFR-002).
  • Interpretation temptation. Reading a favourable basis/resolution as "the" answer would be selective reporting. Mitigation: all four (basis × resolution) budgets reported; verdict stated once across them (NFR-003).
  • Rejected: using the CREA benchmark to tune or validate the partition — structurally excluded (no benchmark argument), exactly as NOX-003.1 excluded it from smoothness selection.

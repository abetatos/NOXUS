Findings

Non-blocking

IDFindingRecommended action
F1 Term (c)/(d) is a structured-vs-white split, not the literal third nested regressor. The dr2_local field carries the raw structured share (γ0 − ½·mean(Δresidual²))/v, not a regression ΔR². This is a reasonable and honest realisation of the design's own definition of local* and its acknowledged "structured vs noise boundary" risk, and it is documented in-code. It is a genuine methodological choice that a future reader should not have to re-derive. Surface as a decision-log entry (see Decision-log proposals D1) and add one sentence to the exploration write-up + findings note stating the ½·mean(Δresidual²) white-noise estimator and its smooth-structured / white-retrieval assumption (already stated in Q2's independence caveat). Reconcile the design prose so the nested-regressor description and the structured-vs-white implementation agree.
F2 CLI verb naming inconsistency. Implementation ships noxus variance (per assumption A3, which governs). design.html (Files-to-change + CLI tab) and tasks T7 still say variance-decomp. Documenter to reconcile design.html + T7 to variance (or add an explicit "A3 supersedes" note). No code change required.
F3 EDGE-004 GeometryError path is not exercised end-to-end. The partition gracefully drops the regional split when the background series is missing/degenerate (tested), but the disk driver _level_series_for_cube calls the real background_ring, which raises GeometryError before the partition sees a degenerate ring. A truly empty ring on the real cube would surface as an uncaught GeometryError rather than a labelled "budget without regional split". Low risk on the real Tangshan cube (ring is well populated). Optional: wrap the regional-series build in the driver to fall back to background=None + no_regional flag, or note the limitation in the findings. Not required for approval.
F4 Single deseason variant per run. REQ-002 references both the intensity-model residual and harmonic-K1 variants; the driver runs one config-selected deseason_method (default harmonic) as the single "deseason" basis. This is consistent with the 4-cell design (AT4 expects exactly 4 rows = 2 bases × 2 resolutions), so it is not a coverage gap — the variant is a config knob, not a separate row. No action required; noted for clarity. If the developer wants both variants contrasted, that is a follow-up, not a spec violation.

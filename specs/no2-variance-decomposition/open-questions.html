Q1 Should a commonality/Shapley variance split be added alongside the sequential ΔR²? Non-blocking
Question
The budget is estimated as sequential nested ΔR² in a fixed entry order (A1/A2). If regional, meteo and steel-local variance are strongly collinear, the order determines who "owns" the shared part. Do you want a symmetric commonality / Shapley (LMG) decomposition reported alongside, so the steel-local share is bracketed between the conservative (last-entry) and symmetric estimates?
Why it matters
It changes how defensible the headline steel-local share is if collinearity is high; a Shapley bracket makes the order-dependence quantitative rather than a caveat.
Blocking
No
Default assumption if not answered
Ship the conservative sequential ΔR² only (A1/A2), report the raw per-step ΔR² and state the order-dependence (EDGE-001). A Shapley variant can be added later without changing the public interface.

noxus/signal/variance.py; design "Variance-partition estimator"; REQ-020/021, EDGE-001

Q2 Is the sqrt(share) → correlation-ceiling mapping the ceiling you want quoted? Non-blocking
Question
REQ-030 reports the change-detector ceiling as ≈ sqrt(steel-local variance share) — the maximum |r| attainable if the steel-local component were a perfect proxy for true steel-activity change and the rest were independent noise. This is an upper bound under an independence assumption. Do you want any additional ceiling framing (e.g. an attenuation-for-retrieval-noise variant, or an R²-based statement), or is the single sqrt(f) mapping sufficient?
Why it matters
Only affects how the ceiling is presented; the measured shares are unchanged. A single clear mapping keeps the message crisp; extra variants add rigour but clutter.
Blocking
No
Default assumption if not answered
Report the single ≈ sqrt(f) ceiling with an explicit statement of the independence assumption behind it, contrasted with ≈ sqrt(attributable_cap) for the level ceiling (REQ-030/031).
Affected files / sections
design "Implied change-detector ceiling"; REQ-030/031; findings note
